<task type="auto">
  <name>Task 1: Create SpeedConfig singleton</name>
  <files>src/config/SpeedConfig.ts</files>
  <action>
Create a mutable module-level singleton (same pattern as DataLoader — `export const SpeedConfig = { ... }` object, NOT a class).

Four presets as a const array:
```
type SpeedPreset = 'Slow' | 'Normal' | 'Fast' | 'Instant';
```

Module-level mutable state:
- `let currentPreset: SpeedPreset = 'Normal'` (default, resets every app open)

Exported singleton methods:
- `current(): SpeedPreset` — returns current preset name
- `cycle(): SpeedPreset` — advances to next preset in order: Normal -> Fast -> Instant -> Slow -> Normal. Returns the NEW preset after cycling.
- `multiplier(): number` — returns the timing multiplier for the current preset:
  - Slow: 2.0 (animations take 2x longer)
  - Normal: 1.0 (baseline)
  - Fast: 0.5 (animations at half duration)
  - Instant: 0 (skip all animation — caller checks for 0 to skip entirely)
- `isInstant(): boolean` — convenience check for `currentPreset === 'Instant'`
- `reset(): void` — resets to Normal (used in tests or if needed)

NOTE: This phase does NOT wire SpeedConfig into AnimationEngine timing. That happens in Phase 8. This phase only creates the singleton and menu integration.
  </action>

`npx tsc --noEmit` passes. Import SpeedConfig in a quick check: `current()` returns 'Normal', `cycle()` returns 'Fast', `cycle()` returns 'Instant', `cycle()` returns 'Slow', `cycle()` returns 'Normal'. `multiplier()` returns correct values for each preset.
  </verify>
  <done>SpeedConfig singleton exports current(), cycle(), multiplier(), isInstant(), reset(). Default is Normal. Cycle order is Normal -> Fast -> Instant -> Slow -> Normal.</done>
