  <action>
    Create `src/animation/AnimationEngine.ts` exporting the `AnimationEngine` class.

    **Class shape:**
    ```
    class AnimationEngine {
      private cancelled: boolean
      private running: boolean

      skip(): void        -- sets cancelled = true (idempotent)
      isRunning(): boolean -- returns this.running

      async playTurn(
        log: TurnLogEntry[],
        prevState: BattleState,   // state BEFORE turn (HP "from" values)
        nextState: BattleState,   // state AFTER turn (HP "to" values)
        glass: GlassAdapter,
      ): Promise<void>
    }
    ```

    **playTurn() flow:**
    1. Set `cancelled = false`, `running = true`
    2. Iterate over `log` entries. For each entry:
       a. Check `cancelled` -- break if true
       b. Call `playEntry(entry, prevState, nextState, glass)`
       c. Check `cancelled` -- break if true
       d. If not the last entry, `await delay(ANIM.ENTRY_PAUSE_MS)` (~500ms pause between entries)
    3. Set `running = false` in a `finally` block

    **playEntry() logic -- launch concurrent operations:**
    Build an array of Promises and `await Promise.all(tasks)`:

    - ALWAYS: `typewriterText(formatEntry(entry), glass)` -- stream the text for this entry
    - If entry.kind === 'DAMAGE':
      - Determine target side: if entry.actor === 'player', target is 'opponent' (player's move hits opponent); if entry.actor === 'opponent', target is 'player'
      - `spriteFlash(targetSide, 'hit', glass)` -- 2-cycle invert+blank flash
      - `hpDrain(targetSide, entry, prevState, nextState, glass)` -- progressive HP tick-down
    - If entry.kind === 'MISS':
      - `spriteFlash(entry.actor, 'miss', glass)` -- attacker does 1 brief disappear/reappear
    - If entry.kind === 'FAINT':
      - Determine which side fainted from `entry.detail.pokemon` by comparing to prevState's active Pokemon names on each side
      - `spriteFlash(faintedSide, 'faint', glass)` -- 3-cycle flash, then blank (sprite removed)

    **typewriterText(fullText, glass):**
    For i from 1 to fullText.length:
      - If cancelled, break
      - `partial = fullText.slice(0, i)`
      - `await glass.updateText(partial, { left: 'Battle', right: '' })`
      - Check if current char is punctuation (.!?): use ANIM.PUNCTUATION_PAUSE_MS, else ANIM.CHAR_DELAY_MS
      - `await delay(pauseMs)`

    **spriteFlash(side, effect, glass):**
    - Get the normal sprite base64 from SpriteService cache:
      - For side detection, use prevState to get the active Pokemon's dex number
      - Use `SpriteService.getBitmapCached(dexNum)` for opponent (front), `SpriteService.getBackBitmapCached(dexNum)` for player (back)
      - Import DataLoader to resolve species -> dexNum (same pattern as battleHudRenderer: `DataLoader.getPokemon(slug)?.num`)
    - Compute inverted sprite ONCE: `const inverted = await invertSprite(normal)`
    - Get blank: `const blank = blankSprite()`
    - Determine container: use CONTAINER_IDS.oppSprite / CONTAINER_NAMES.oppSprite for opponent, CONTAINER_IDS.playerSprite / CONTAINER_NAMES.playerSprite for player
    - Flash cycles:
      - 'hit': ANIM.HIT_FLASH_CYCLES (2) cycles of: invert -> delay -> restore -> delay -> blank -> delay -> restore -> delay
      - 'miss': 1 cycle of: blank -> delay -> restore -> delay (attacker disappears and reappears)
      - 'faint': ANIM.FAINT_FLASH_CYCLES (3) cycles of same pattern as hit, then final `updateImage(containerID, containerName, blank)` to permanently remove sprite
    - Each step: `await glass.updateImage(containerID, containerName, imageData)` then `await delay(ANIM.FLASH_FRAME_MS)`
    - Check `cancelled` before each frame -- break if true

    **hpDrain(side, entry, prevState, nextState, glass):**
    - Get the damage from `entry.detail.damage as number`
    - Get the active Pokemon from prevState for the target side: `prevState[side + 'Side'].team[prevState[side + 'Side'].activeIndex]`
    - startHp = prevState mon's currentHp (HP before this hit)
    - endHp = startHp - damage (but floor at 0)
    - steps = Math.min(Math.abs(damage), ANIM.MAX_HP_STEPS)
    - For i from 0 to steps:
      - If cancelled, break
      - currentHp = Math.round(startHp - (damage * i / steps))
      - Create a temporary mon copy with this currentHp
      - Build HP text using formatHpBar(tempMon)
      - `await glass.updateText(hpDisplayText, { left: 'Battle', right: '' })`
      - `await delay(ANIM.HP_FRAME_MS)`
    - Note: the typewriter text and HP drain share the text container (ID 1). Since they run concurrently via Promise.all, the last write wins per frame. This is acceptable -- the typewriter reveals narration text while HP updates show alongside. For simplicity, during HP drain frames, update the text container with a combined string: the current typewriter text (already fully revealed by this point since HP drain starts concurrently but the text is short) plus the HP bar on a new line. OR simpler approach: let typewriter own the text container exclusively, and represent HP drain purely through the status bar (left = HP info, right = progress). RECOMMENDED: Keep it simple -- typewriter owns the text container. HP drain updates the STATUS BAR left side with the draining HP value using `glass.updateText()`. This avoids container conflicts. The status bar already supports updateText via textContainerUpgrade on CONTAINER_IDS.status.

    **IMPORTANT STATUS BAR APPROACH FOR HP DRAIN:** Instead of fighting over container ID 1 with typewriter, update the status bar (container ID 2) with draining HP. Call `glass.updateText()` which updates all three text containers (content, status, statusRight). For HP drain frames, pass the current typewriter text as the main text (or the full text if typewriter is done) and put HP info in the status bar. Actually, `glass.updateText(text, status)` updates content + status + statusRight in a single call. So both typewriter and HP drain need to coordinate.

    SIMPLEST CORRECT APPROACH: Do NOT make HP drain concurrent with typewriter. Instead, run them sequentially within playEntry:
    1. First: typewriter text (uses updateText with narration text)
    2. Then: HP drain (uses updateText with narration text frozen, just changing the HP portion in the status bar)

    BUT the user explicitly wants concurrent. So use this approach: spriteFlash runs independently (updateImage on containers 4/5). Typewriter and HP drain BOTH call updateText, but they coordinate: typewriter reveals text char by char in the content area. HP drain updates the status bar. Since updateText() writes all three containers atomically, we need a shared mutable reference for the "current text" that both can read.

    FINAL APPROACH (cleanest):
    - Create a mutable `currentText` string variable in playEntry scope
    - Typewriter updates `currentText` as it reveals chars, then calls `glass.updateText(currentText, { left: hpStatus, right: '' })`
    - HP drain updates `hpStatus` string, then calls `glass.updateText(currentText, { left: hpStatus, right: '' })`
    - Both reference the shared variables. Last writer wins per BLE cycle, which is fine -- both converge to the final state.
    - Initialize `currentText = ''` and `hpStatus = 'Battle'` at start of playEntry.

    **delay(ms) helper:**
    ```typescript
    private delay(ms: number): Promise<void> {
      return new Promise(r => {
        if (this.cancelled) { r(); return; }
        setTimeout(r, ms);
      });
    }
    ```
