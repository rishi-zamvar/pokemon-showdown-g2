# Phase 5.1 Plan 02: AnimationEngine Summary

**One-liner:** Async sequencer driving Game Boy-style typewriter text, sprite flash, and HP drain concurrently per turn log entry with tap-to-skip cancellation.

## What Was Built

AnimationEngine class (217 lines) that receives a turn log and battle states, then orchestrates timed calls to `glass.updateText()` and `glass.updateImage()` to create animated turn resolution.

### Key Components

1. **playTurn()** -- iterates log entries with ENTRY_PAUSE_MS gaps, sets running/cancelled flags
2. **playEntry()** -- launches concurrent effects via Promise.all based on entry kind
3. **typewriterText()** -- reveals text char-by-char with punctuation pauses (45ms/char, 180ms for .!?)
4. **spriteFlash()** -- invert-restore-blank-restore cycles using SpriteEffects primitives
   - DAMAGE: 2-cycle hit flash on target
   - MISS: 1-cycle disappear/reappear on attacker
   - FAINT: 3-cycle flash then permanent blank
5. **hpDrain()** -- progressively ticks HP bar from old to new value over MAX_HP_STEPS frames
6. **skip()** / **isRunning()** -- cancellation flag and playback state tracking

### Concurrency Model

Text and HP drain both update shared `currentText` and `hpStatus` variables, calling `glass.updateText()` independently. Sprite flash uses `glass.updateImage()` on different containers (4/5 vs 1/2/3), avoiding BLE contention.

## Decisions Made

| ID | Decision | Rationale |
|----|----------|-----------|
| 05.1-02-01 | Shared mutable state for text+HP | Both effects need to call updateText with latest values from the other |
| 05.1-02-02 | findFaintedSide by name match | FAINT entries have pokemon name in detail but no side field |
| 05.1-02-03 | HP drain from prevState.currentHp | prevState has "before" HP; damage subtracted progressively |
