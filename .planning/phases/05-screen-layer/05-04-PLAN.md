# Plan 05-04: ASCII Art Sprites on G2 Display

## Context

Phase 5 (Screen Layer) had 3 plans. This plan adds ASCII art Pokemon sprites
to the G2 glasses display — sprites shown as background with battle info
overlaid in the foreground.

**Data source**: [vsoch/pokemon](https://github.com/vsoch/pokemon) —
`pokemons.json` with ASCII art for 890 Pokemon. Each entry has `id`, `name`,
`ascii` (newline-separated string, ~27 lines x ~57 chars). Sprites are
center-cropped to fit G2 constraints (30 chars x 6 lines).

## Files Created

| File | Purpose |
|------|---------|
| `src/sprites/SpriteService.ts` | Fetch from vsoch/pokemon, center-crop to 6x30, cache to localStorage |
| `src/screens/renderers/spriteRefreshRenderer.ts` | "< Back / Mine / Theirs / Both" list renderer |

## Tasks

### Task 1: Create SpriteService singleton
- **Status**: complete
- Fetches full pokemons.json from vsoch/pokemon GitHub raw URL
- Center-crops ~27-line ASCII art to 6 lines x 30 chars
- Caches cropped sprites to localStorage (`ascii-sprite-{dexNum}`)
- Check cache before fetching; only fetch missing sprites
- `clearCache(dexNumbers[])` and `clearAllCache()` for refresh flow

### Task 2: Create spriteRefreshRenderer + SPRITE_REFRESH screen
- **Status**: complete
- Added `SPRITE_REFRESH` to ScreenName union in ScreenState.ts
- Created spriteRefreshRenderer returning list: `['< Back', 'Mine', 'Theirs', 'Both']`

### Task 3: Modify battleHudRenderer for sprite compositing
- **Status**: complete
- 8-line layout: Lines 0-5 = ASCII sprite, Line 6 = separator, Line 7 = player info
- Opponent info right-aligned on line 0 over sprite
- `compositeOnSprite()` overlays text onto sprite line at right edge
- Falls back to plain text when no sprite cached

### Task 4: Update mainMenuRenderer and ScreenController
- **Status**: complete
- Main menu now shows `['Enter Battle', 'Refresh Sprites']`
- `startNewBattle()` collects dex numbers, fires `SpriteService.fetchAndCache()` in background
- `handleMainMenu()` routes idx 0 to battle, idx 1 to SPRITE_REFRESH
- `handleSpriteRefresh()` clears appropriate cache keys, shows confirmation message
- Tracks `playerDexNums` and `opponentDexNums` for targeted refresh

## Verification

- `npx tsc --noEmit` passes
- `npm run build` succeeds (224 modules, 9.2MB bundle)
- Battle HUD shows ASCII art background with info overlay when sprite cached
- Sprites load from vsoch/pokemon on first battle, from localStorage on subsequent
- "Refresh Sprites" menu works with Mine/Theirs/Both options
- Fallback to plain text when sprite not available
- Display stays within 900 char / 64 char per line / 8 line budget
