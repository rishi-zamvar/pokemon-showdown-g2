Replace the placeholder app logic (the "Hello from G2!" message and example gesture handler) with:

```typescript
import { GlassAdapterImpl } from './adapters/glassAdapter';
import { WakeLockServiceImpl } from './services/wakeLockService';
import { DataLoader } from './data/DataLoader';
import { ScreenController } from './screens/ScreenController';

function setStatus(text: string, detail?: string): void {
  // Keep existing implementation
}

async function bootstrap(): Promise<void> {
  setStatus('Connecting to glasses...', 'Open this page from Even App dev mode');

  const glass = new GlassAdapterImpl();
  const wakeLock = new WakeLockServiceImpl();

  await glass.connect();

  const dot = document.getElementById('status-dot');
  if (dot) dot.className = 'status-indicator connected';
  setStatus('Connected');

  try {
    DataLoader.validate();
    console.log('[DataLoader] All data files validated successfully');
  } catch (err) {
    console.error('[DataLoader] Data validation failed:', err);
    setStatus('Data error', String(err));
    return;
  }

  // Initialize screen controller and show main menu
  const screen = new ScreenController(glass);
  await screen.init();

  setStatus('Ready', 'Battle on your glasses!');

  // Route all gestures through the screen controller
  glass.onGesture((event) => {
    void screen.handleGesture(event);
  });

  // Keep screen on during gameplay
  try {
    await wakeLock.acquire();
  } catch {
    console.warn('[WakeLock] Could not acquire wake lock');
  }
}

void bootstrap().catch((error: unknown) => {
  setStatus('Failed to start', String(error));
  const dot = document.getElementById('status-dot');
  if (dot) dot.className = 'status-indicator error';
  console.error('G2 app failed to start', error);
});
```

Add a private method `updatePhoneCompanion()` to ScreenController that updates the phone's HTML companion display with current battle state.

**Wiring into render(): At the end of the `render()` method, append the following call:**
```typescript
if (this.state.battleState) {
  this.updatePhoneCompanion();
}
```
This ensures the phone companion updates on every screen transition, turn result, and FOREGROUND_ENTER re-render.

**`private updatePhoneCompanion(): void`:**

1. Get the companion container: `document.getElementById('battle-companion')`
2. If no battleState or no companion element, return
3. Show companion (remove 'hidden' class), hide status screen (add 'hidden' to `status-screen`)
4. Get player and opponent active Pokemon from battleState
5. Update sprites using PokeAPI CDN:
   - Get dex number: `DataLoader.getPokemon(species.toLowerCase().replace(/[^a-z0-9]/g, ''))?.num`
   - Sprite URL: `https://raw.githubusercontent.com/PokeAPI/sprites/master/sprites/pokemon/${num}.png`
   - Set `img.src` and `img.alt` for both `#player-sprite` and `#opp-sprite`
   - If num not found, set `img.src = ''` (blank)
6. Update names: `#player-name` and `#opp-name` with `.name`
7. Update HP bars:
   - Calculate HP percentage: `Math.max(1, Math.round((currentHp / stats.hp) * 100))` for non-fainted; `0` for fainted
   - Set `#player-hp-bar` width: `style.width = '${hpPct}%'`
   - Set bar color: `hpPct > 50 ? '#4cd964' : hpPct > 25 ? '#f5a623' : '#ff3b30'`
   - Set `#player-hp-text` and `#opp-hp-text`: `"{currentHp}/{maxHp} ({pct}%)"`
8. Update companion log (`#companion-log`) with last turn log entries (if any):
   - Reuse the same formatting as turnResultRenderer but in HTML div format
   - Each log entry as a `<div class="log-line {cssClass}">{text}</div>`
   - CSS class: 'damage' for DAMAGE/FAINT, 'info' for TERA/SWITCH, 'good' for WIN

**When battle ends (END_SCREEN):**
- Show "Victory!" or "Defeat" in companion header
- Keep sprites visible

**When returning to MAIN_MENU:**
- Hide companion (add 'hidden' class), show status screen (remove 'hidden')

**Important:** Use `DataLoader.getPokemon()` for dex number lookup. The species field on ActivePokemon is the Showdown species name. Use `.toLowerCase().replace(/[^a-z0-9]/g, '')` to normalize to a lookup slug, matching the DataLoader key format (decision from 01-01: PS data keys are lowercase slugs).
