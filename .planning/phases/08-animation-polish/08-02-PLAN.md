**Create src/animation/TextBoxRenderer.ts:**

A pure function that wraps animation text in a classic Pokemon-style text box using Unicode double-line box drawing characters.

```
export function renderTextBox(text: string, lineWidth: number = 62): string
```

Box drawing characters: top-left, top-right, bottom-left, bottom-right, horizontal, vertical, space padding.
- Top border:    `+` + `=` repeated + `+` (use ASCII for G2 compatibility — Unicode box drawing chars may not render on the monochrome display)
- Side borders:  `|` + content padded to lineWidth + `|`
- Bottom border: `+` + `=` repeated + `+`

Actually, FIRST check if G2 supports Unicode box drawing. The G2 display renders text via SDK TextContainerProperty. Since the context decisions say "Double-line Unicode box drawing characters", use them:
- Top: `\u2554` + `\u2550` repeated + `\u2557`  (upper-left, horizontal, upper-right)
- Sides: `\u2551` + text + `\u2551`              (vertical bars)
- Bottom: `\u255A` + `\u2550` repeated + `\u255D` (lower-left, horizontal, lower-right)

The function:
1. Takes the raw text string and wraps it into lines that fit inside the box (lineWidth - 4 chars for borders + padding).
2. Word-wraps long lines.
3. Pads short lines with spaces to fill the box width.
4. Returns the complete box as a multi-line string.
5. Box has room for 3-4 content lines. If text exceeds 4 lines, truncate to last 4 lines (most recent text visible).

lineWidth default = 62 (leaving 2 chars margin on each side of the 64-char G2 line).

**Wire into AnimationEngine:**

In AnimationEngine's `playEntry` method, modify the `updateDisplay` closure:
1. Import `renderTextBox` from `./TextBoxRenderer.js`.
2. In the updateDisplay closure, wrap `currentText` with `renderTextBox(currentText)` before passing to `glass.updateText()`.
3. The HP status string continues to go in the StatusBar left field (unchanged).

This means during animation, instead of raw text appearing directly, it appears inside the bordered frame. The typewriter effect still works — each character added causes a re-render of the box with the growing text.

For the SWITCH entry (where text comes after animation), the same pattern applies — the typewriter text is wrapped in the text box.

IMPORTANT: The text box frame should persist across all entries in a turn. The `playTurn` method calls `playEntry` for each log entry. Each entry's text replaces the previous entry's text inside the same box frame. The box itself stays consistent.

<task type="auto">
  <name>Task 2: Add lunge animation for contact/physical attacking moves</name>
  <files>src/animation/AnimationEngine.ts, src/config/constants.ts</files>

Add attack lunge animation: when a Pokemon uses a contact move, its sprite shifts toward the opponent before the hit flash plays.

**Add ANIM constants to constants.ts:**
```typescript
/** Pixel offset for attack lunge (% of screen width approximated). */
LUNGE_OFFSET_PX: 10,
/** Number of frames for the lunge forward motion. */
LUNGE_FRAMES: 2,
/** Duration of each lunge frame (ms) — uses base timing, will be speed-scaled. */
LUNGE_FRAME_MS: 60,
```

**Add lunge logic to AnimationEngine:**

1. Add a private method `isContactMove(moveSlug: string): boolean`:
   - Look up the move via `DataLoader.getMove(moveSlug.toLowerCase())`
   - Return true if: `move.category !== 'Status'` AND `move.flags?.contact` is truthy
   - Status moves NEVER lunge (per context decisions)
   - Special moves without contact flag do NOT lunge (ranged attacks like Thunderbolt)
   - Physical/Special moves WITH contact flag DO lunge (Close Combat, U-turn, Grass Knot)

2. Add a private async method `lungeAnimation(side: Side, state: BattleState, glass: GlassAdapter): Promise<void>`:
   - Get the sprite for the given side
   - Determine lunge direction: player lunges RIGHT (toward opponent), opponent lunges LEFT (toward player)
   - For player (bottom-left sprite): shift sprite RIGHT by LUNGE_OFFSET_PX * frame
   - For opponent (top-right sprite): shift sprite LEFT by -LUNGE_OFFSET_PX * frame
   - Use `shiftSpriteBmp()` (already exists in AnimationEngine module scope) to create shifted frames
   - Push LUNGE_FRAMES frames with scaledDelay(LUNGE_FRAME_MS) between each
   - After the last frame, snap back to original position instantly (replace with original sprite, no smooth slide back — per context decisions)

3. Modify `playEntry` DAMAGE case:
   - Before `this.spriteFlash(targetSide, 'hit', ...)`, check if the preceding MOVE_USE entry's move is a contact move.
   - The MOVE_USE entry is the entry immediately before DAMAGE in the log. Since playEntry processes one entry at a time, we need to track the last move used.
   - Add a private field `private lastMoveSlug: string = ''` to AnimationEngine class.
   - In playEntry, when entry.kind === 'MOVE_USE', store `this.lastMoveSlug = String(entry.detail.move ?? '')`.
   - In the DAMAGE case, check `this.isContactMove(this.lastMoveSlug)`. If true, run `await this.lungeAnimation(entry.actor, prevState, glass)` BEFORE the spriteFlash (the attacker lunges, then the target flashes from the hit).
   - Add the lunge promise to the tasks array BEFORE spriteFlash, but since lunge must complete before flash, use `await` for lunge first, then push remaining tasks to Promise.all.

4. Reset `lastMoveSlug = ''` at the start of `playTurn` to prevent stale state.

IMPORTANT: The lunge is from the ATTACKER's side (entry.actor for DAMAGE entries is the attacker). The flash is on the TARGET side (already opposite). So lunge uses entry.actor, flash uses targetSide. After lunge, snap back immediately — no smooth return animation.
