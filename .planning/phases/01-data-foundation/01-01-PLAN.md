<task type="auto">
  <name>Task 1: Create fix-data.mjs fetch script</name>
  <files>scripts/fix-data.mjs</files>
  <action>
Create `scripts/fix-data.mjs` — a Node.js ESM script that:

1. Defines three targets:
   - `https://play.pokemonshowdown.com/data/abilities.js` -> `BattleAbilities` -> `src/data/abilities.json`
   - `https://play.pokemonshowdown.com/data/items.js` -> `BattleItems` -> `src/data/items.json`
   - `https://play.pokemonshowdown.com/data/typechart.js` -> `BattleTypeChart` -> `src/data/typechart.json`

2. For each target:
   - Fetch the .js URL (NOT .json — the .json URLs return 404 HTML)
   - Guard: if response body starts with `<!` or `Content-Type` is `text/html`, throw with a clear error
   - Strip the CommonJS wrapper using `vm.createContext` + `vm.runInContext` with a `{ exports: {} }` sandbox
   - Extract `sandbox.exports[exportKey]`
   - Validate: the extracted object must have at least 10 keys (abilities should have 200+, items 100+, typechart 18+)
   - Write to disk with `JSON.stringify(data, null, 2)` for readable diffs
   - Log: file path and entry count

3. Add an `npm run fix-data` script to package.json: `"fix-data": "node scripts/fix-data.mjs"`

Use `import { createContext, runInContext } from 'vm'` and `import { writeFileSync } from 'fs'`. Use `import { dirname, join } from 'path'` and `import { fileURLToPath } from 'url'` for path resolution.

Note: JSON.stringify will drop function-valued keys (onStart, onModifyAtk, etc.) from abilities and items. This is expected and correct for Phase 1 — we only need name, num, desc, flags, rating fields. The battle simulation hooks come from @pkmn/sim later if needed.
  </action>
  <verify>Run `node scripts/fix-data.mjs` and confirm it completes without errors, logging entry counts for all three files.</verify>
  <done>scripts/fix-data.mjs exists; running it produces three valid JSON files with correct entry counts.</done>
</task>
