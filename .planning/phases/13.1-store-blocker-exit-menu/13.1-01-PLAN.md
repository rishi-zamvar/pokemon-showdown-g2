method that fires the exit dialogue.

```typescript
class MenuItemProperty {
  itemName?: string;   // <= 32 UTF-8 BYTES, not characters
  itemID?: number;     // non-zero, unique within the menu
  constructor(data?: Partial<MenuItemProperty>);
}

class MenuContainerProperty {
  menuItems?: MenuItemProperty[];   // firmware accepts at most 10
  constructor(data?: Partial<MenuContainerProperty>);
}

// Already on EvenHubEvent, alongside listEvent / textEvent / sysEvent:
type EvenHubEvent = { ...; menuItemClickEvent?: MenuItemClickEvent; };
class MenuItemClickEvent { itemID?: number; }

// Already on EvenAppBridge:
//   exitMode 0 = close immediately
//   exitMode 1 = raise the foreground interaction layer, i.e. THE DIALOGUE
shutDownPageContainer(exitMode?: number): Promise<boolean>;

// The page-config shape the SDK validator accepts:
type EvenHubPageContainerLike = {
  listObject?: ...; textObject?: ...; imageObject?: ...;
  menuObject?: MenuContainerProperty | Record<string, any>;
};
```

MENU VALIDATION IS ALREADY DONE FOR YOU — DO NOT WRITE A NEW GUARD.
`glassAdapter.assertPage()` already calls `validateEvenHubPageContainer(config)`
before every create/rebuild. Probed live against 0.0.15 with the installed
package, that validator returns:

    itemID: 0          -> {valid:false, code:"INVALID_MENU_ITEM_ID"}
    duplicate itemID   -> {valid:false, code:"DUPLICATE_MENU_ITEM_ID"}
    11 items           -> {valid:false, code:"TOO_MANY_MENU_ITEMS"}
    33-byte itemName   -> {valid:false, code:"INVALID_MENU_ITEM_NAME"}
    9x "🎮" (36 bytes) -> {valid:false, code:"INVALID_MENU_ITEM_NAME"}   // BYTES, confirmed
    {itemID:1,itemName:"Exit"} -> {valid:true}

So D-07's "validate before the SDK call" is satisfied for free the moment
`menuObject` is part of the object handed to `assertPage`. The ONLY thing that
can break it is building the menu AFTER the validation call. Build it before.

`assertPageContainers` (containerGuards.ts) counts `listObject + textObject +
imageObject` only and never looks at `menuObject`. That is correct: a menu is
not a container. `containerTotalNum` must NOT include menu items.

In `bindEvents`, handle the menu event FIRST and RETURN, before

```typescript
this.unsubscribeHub = this.bridge.onEvenHubEvent((event) => {
  // INPUT-02, and it MUST be tested before mapEventToGesture (D6 / Phase 16):
  // that function maps EVERY unrecognised eventType — including `undefined`,
  // which is how the SDK deserialises CLICK_EVENT=0 — to TAP. A menu click
  // carries no eventType at all, so falling through would turn "the wearer
  // opened the menu and chose About" into a stray TAP that commits a move.
  // Presence of the object is the test, NOT `itemID !== undefined`: an event
  // that arrives with the id missing must still be swallowed here, never
  // handed to the gesture mapper.
  if (event.menuItemClickEvent) {
    const itemID = event.menuItemClickEvent.itemID;
    if (itemID === undefined) {
      console.log('[GlassAdapter] menuItemClickEvent with no itemID — ignored');
      return;
    }
    // The firmware emits DUPLICATE events ~50-100 ms apart for one physical
    // transition. Undeduped, one selection of "Exit" fires the dialogue twice
    // and one selection of "Battle Speed" skips a preset. Same shape as the
    // existing 300 ms SCROLL cooldown, wider window because the consequence
    // of a double Exit is unrecoverable (D-02).
    const now = Date.now();
    if (itemID === this.lastMenuItemID && now - this.lastMenuItemTime < MENU_DEDUPE_MS) {
      console.log(`[GlassAdapter] menu: duplicate itemID=${itemID} within ${MENU_DEDUPE_MS}ms — dropped`);
      return;
    }
    // Refreshed on ACCEPT only, never on a drop: the window measures time
    // since the last DELIVERED click, so a burst cannot extend itself
    // indefinitely. Irrelevant at the observed 50-100 ms duplicate spacing;
    // stated because the alternative is a silently different policy.
    this.lastMenuItemID = itemID;
    this.lastMenuItemTime = now;

    console.log(`[GlassAdapter] menu: itemID=${itemID}`);
    for (const handler of this.gestureHandlers) {
      handler({ kind: 'MENU_ITEM', menuItemID: itemID });
    }
    return;
  }

  const gesture = this.mapEventToGesture(event);
  ... existing body unchanged ...
});
```

Add the two private fields next to `lastScrollTime` (`private lastMenuItemID:

Do NOT touch `mapEventToGesture`. Do NOT widen the existing scroll cooldown to

Do NOT add any host call. The menu is declared with the page that was going to
