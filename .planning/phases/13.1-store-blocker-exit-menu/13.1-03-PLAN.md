<objective>
Turn the three claims this phase makes into things a run can fail on.

The interesting assertion is a negative one. The failure mode this phase exists
to prevent is an UNINTENDED exit: the dialogue, once dismissed, leaves every
`updateImageRawData` returning `sendFailed` until the app restarts, so an app
that exits when it should not is not merely wrong, it is bricked for the rest
of the session. Absence of the exit line across a full battle IS the assertion
(D-11).

The second interesting thing is what the harness deliberately does NOT do: it
never selects Exit. Firing the dialogue mid-run would wedge every image send
that follows and turn one intentional check into a cascade of unrelated
failures. Exit's wiring is proved statically (plan 02's grep gate: exactly one
call site, behind a root-only guard); the harness proves the menu is live, that
clicks route, and that nothing fires the exit by accident.

Purpose: HARN-* already gates this repo. This plan makes 13.1 gated too.
Output: one negative assertion helper, three selfCheck checks, two boot steps,
one battle assertion.
</objective>

In `harness/assert.ts`, add the negative counterpart to `expectLoggedLine`. It
has two callers in this plan, which is why it is a helper rather than an inline
`find`:

```typescript
/**
 * The assertion INPUT-05 actually needs (D-11). The failure this phase exists
 * to prevent is an exit that was never asked for, and the only evidence of it
 * is a line that should not be there — so the check has to be shaped as an
 * absence. Reports the offending line, not just "found one", because
 * "something exited" with no context is an unactionable failure report.
 */
export function expectNoLoggedLine(logs: LogStream, pattern: RegExp, why: string): void {
  const hit = logs.all().find((l) => pattern.test(l.message));
  if (!hit) return;
  throw new AssertionError(
    `${why}: log line matched ${pattern} — [${hit.source}/${hit.level}] ${hit.message}`,
  );
}
```

In `harness/selfCheck.ts`, APPEND checks after check 52 — never renumber or
weaken an existing one. Import `MAIN_MENU_CONTEXT_MENU` and `MENU_ITEM_IDS`
from `../src/config/constants.ts` (that import already exists; extend it).

Check 53 — the four protocol rules, enforced locally so no SDK import is
needed and containerGuards' zero-import rule is untouched:
  - every `id` is a non-zero integer;
  - all `id`s are unique;
  - `MAIN_MENU_CONTEXT_MENU.length <= 10`;
  - `Buffer.byteLength(name, "utf8") <= 32` for every name — assert BYTES, and
    include a positive control proving the check would catch a multi-byte name
    that is under 32 CHARACTERS but over 32 bytes (e.g. `"é".repeat(20)` is 20
    chars / 40 bytes and must be rejected by the same predicate). A
    character-length check would pass that and the firmware would truncate a
    name the app can never address again.
  This is the check that stops Phase 17 from adding an 11th inspect entry or an
  over-long label and only finding out when a rejected page builds NOTHING.

Check 54 — Exit is last, and the ids are stable:
  `MAIN_MENU_CONTEXT_MENU.at(-1).id === MENU_ITEM_IDS.exit`, with the reason in
  the failure message: a default highlight lands on the FIRST item, and D-02
  makes an accidental Exit unrecoverable until restart.

Check 55 — `containerTotalNum` counts containers, not menu items. Build the
root page config the app really sends (one `ListContainerProperty`-shaped
object with `isEventCapture: 1`, one status text container with
`isEventCapture: 0`, `containerTotalNum: 2`) plus a `menuObject` carrying three
items, and assert `assertPageContainers(config)` accepts it unchanged. Then
assert it REFUSES the same config with `containerTotalNum: 5` (2 containers +
3 menu items), naming the mistake: a menu is not a container, and counting menu
items into the total makes the guard refuse every correct root page.
  Use the existing local structural helpers in this file (`ContainerLike` /
  `PageConfigLike`) — `assertPageContainers` never looks at `menuObject`, which
  is the property being pinned here.

Follow the file's existing `check("NN name", () => {...})` shape and the
existing `refuses...` helper style for the negative arms.
