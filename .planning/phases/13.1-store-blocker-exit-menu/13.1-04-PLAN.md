<objective>
Close INPUT-05 with the two assertions that are actually load-bearing: that the
exit never fires when nobody asked, and that it DOES fire when somebody did.

The negative half currently cannot work. `ctx.step()` calls `logs.reset()`,
which empties the line buffer, so an `expectNoLoggedLine` placed after
`runBattleScript` sees nothing the battle logged and would pass even if the app
exited on every single turn. It has to live inside each turn's own step.

The positive half has nowhere safe to live — except last. Firing the dialogue
wedges every subsequent `updateImageRawData` for the rest of the session
(D-02), and the suite shares one simulator. Run it as the final scenario and
the wedge has nothing left to poison. This is a better proof than a mocked one:
it exercises the real gesture path, the real adapter, and the real bridge.

Purpose: INPUT-05 is the submission blocker; nothing in the phase currently
observes its call actually happening.
Output: one per-turn assertion, one rewritten step, one terminal scenario.
</objective>

WHY "ACROSS runBattleScript" IS VACUOUS — run.ts:173-177:

```typescript
async step(name, fn, opts) {
  if (sim) collectWaived(logs);
  if (sim && !opts?.keepLogs) await logs.reset();   // <- logs.ts:166 sets this.lines = []
  ...
}
```

`LogStream.reset()` is `this.lines = []`. So `logs.all()` only ever holds the
CURRENT step's lines. `stdoutLineCount` is the one field deliberately exempted
("Monotonic for the LIFETIME of this object — reset() must not zero it"),
which is the precedent if a surviving counter is ever wanted. The correct fix
here is simpler: assert inside the step that produced the lines.

THE PLACE IT GOES — battle.ts:443-446, the end of each `turn-${turn}` step:

```typescript

      // assertion that catches a container-validation line appearing on turn 17.

    });
```
