**Random AI opponent that reads legal moves from @pkmn/sim ChoiceRequest and returns PlayerAction for SimBattleAdapter translation**

## Accomplishments

- SimAIOpponent singleton created with pickAction() and pickSwitch() reading from live sim state
- Handles all three ChoiceRequest variants: WaitRequest (struggle fallback), SwitchRequest (forceSwitch), MoveRequest (random legal move)
- Tera usage at 20% probability when canTerastallize flag is set in request
- No @smogon/calc or DataLoader dependency — pure sim state reads
- `npx tsc --noEmit` passes with zero errors

## Files Created/Modified

- `src/battle/SimAIOpponent.ts` - AI singleton reading from battle.sides[1].activeRequest; pickAction returns PlayerAction for all request types; pickSwitch returns 0-based team index for forced switches

## Decisions Made

- `activeRequest` is cast as `any` for safe property narrowing — the ChoiceRequest union from @pkmn/sim has `wait`, `forceSwitch`, and `active` as discriminating fields that are reliably present; importing the full union type would require re-exporting internal types that aren't cleanly exposed.
- Random move selection chosen over damage scoring — this plan explicitly replaces AIOpponent.ts's @smogon/calc approach; the sim's ChoiceRequest guarantees only legal moves are listed, so random selection is correct and matches PS's built-in RandomPlayerAI.
- Tera probability kept at 20% via `canTerastallize` field — the sim tracks whether Tera has been used internally; no need for a separate `teraUsed` flag in SimAIOpponent.
- `_pickForceSwitchIndex` skips `forceSwitch.length` slots (active slots count) then searches for first non-fainted entry using `condition.endsWith(' fnt')` — matches @pkmn/sim's PokemonSwitchRequestData format.
- `pickSwitch` has a secondary fallback scanning `battle.sides[1].pokemon` directly when `activeRequest` has no forceSwitch — covers edge cases where the method is called outside a forced-switch context.

## Issues Encountered

None. The @pkmn/sim type declarations clearly defined `PokemonMoveRequestData`, `SwitchRequest`, `MoveRequest`, and `WaitRequest` shapes in `side.d.ts`, making the implementation straightforward. The `pp` field on individual moves in a MoveRequest is not always present (only sent when PP is less than max), so an undefined-safe check was included per the actual type definition.
