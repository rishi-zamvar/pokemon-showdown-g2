**Step 5: Update resolveSwitch()**

The current resolveSwitch handles double faint (both sides need to switch). With the sim, both sides submit their switch choices via a single `makeChoices()` call.

Replace the resolveSwitch method body. The new flow:

```typescript
private async resolveSwitch(toIndex: number): Promise<void> {
  let bs = this.state.battleState!;
  const log: TurnLogEntry[] = [];
  const battle = SimBattleAdapter.getBattle()!;

  // Check if opponent's active is also fainted (double faint)
  const opponentSide = bs.opponentSide;
  const opponentActive = opponentSide.team[opponentSide.activeIndex]!;
  if (opponentActive.fainted) {
    // AI picks its switch target
    const aiSwitchIndex = SimAIOpponent.pickSwitch(battle);
    // Submit both switches together via the aiSwitchIndex parameter
    const result = SimBattleAdapter.submitSwitch(bs, 'player', toIndex, aiSwitchIndex);
    log.push(...result.log);
    bs = result.nextState;
  } else {
    // Only player needs to switch
    const result = SimBattleAdapter.submitSwitch(bs, 'player', toIndex);
    log.push(...result.log);
    bs = result.nextState;
  }

  this.lastTurnLog = log;
  this.state = {
    ...this.state,
    battleState: bs,
    cursorIndex: 0,
  };

  // Determine next screen based on resulting phase
  switch (bs.phase) {
    case 'WAITING_FOR_ACTION':
      this.state = { ...this.state, screen: 'BATTLE_HUD' };
      break;
    case 'WAITING_FOR_SWITCH':
      this.state = { ...this.state, screen: 'SWITCH_SELECT' };
      break;
    case 'BATTLE_OVER':
      this.state = { ...this.state, screen: 'END_SCREEN' };
      break;
  }

  await this.render();
}
```

Note: Switch animations are out of scope for this phase — the current codebase does not animate switches (no sprite slide-in/out), so the absence of animation calls in resolveSwitch() is consistent with existing behavior. Switch animation can be added in a future enhancement phase.

IMPORTANT: The double-faint case is tricky with the sim. `battle.makeChoices()` requires both sides. When both sides have `forceSwitch`, SimBattleAdapter.submitSwitch needs to submit both choices at once. The AI switch is determined by SimAIOpponent.pickSwitch(battle) and passed as the `aiSwitchIndex` parameter.

SimBattleAdapter.submitSwitch() already accepts an optional `aiSwitchIndex` parameter (defined in Plan 01 Task 2). When provided, the adapter sends `switch ${toIndex + 1}` for p1 and `switch ${aiSwitchIndex + 1}` for p2 in the same makeChoices call. When omitted (single-side switch), the other side's choice is `pass`.
