## Files Created/Modified

- `src/battle/LogParser.ts` — `parseLogLines(lines: string[]): TurnLogEntry[]` — stateless PS protocol line parser; handles move/damage/miss/faint/status/switch/tera/win/cant/crit commands
- `src/battle/SimBattleAdapter.ts` — module singleton with startBattle/submitAction/submitSwitch/getBattle; wraps @pkmn/sim Battle; includes filterSplitLines(), fillDamageValues(), deriveBattleState(), actionToChoice() helpers
- `src/battle/simSmoke.ts` — smoke test verifying all 3 key behaviors; runs with `npx tsx`

## Decisions Made

- **filterSplitLines approach:** The `send('update', ...)` callback receives ALL log lines including `|split|pX` markers and duplicate secret/shared pairs. Strategy: skip the split marker and the secret (side-specific) line; keep only the shared line. This prevents duplicate TurnLogEntry items per event.

- **HP percentage mod in DAMAGE detail fields:** `targetHp`/`targetMaxHp` in DAMAGE entries come from log strings — which show percentages for opponent pokemon under HP Percentage Mod. These are only used by AnimationEngine for drain animation interpolation, not for state derivation. Real HP is always read from `battle.sides[n].pokemon[i].hp`.

- **damage=0 in LogParser, filled in SimBattleAdapter:** LogParser is stateless and doesn't know prev HP. SimBattleAdapter's `fillDamageValues()` computes real damage from `prevHp` map diff after each turn. This clean separation keeps LogParser simple and testable.

- **getBattle() accessor:** Returns module-scope `battle` instance to SimAIOpponent (Plan 05.2-02) so AI can read `side.activeRequest` directly without coupling to adapter internals.

- **toxicCounter/sleepTurns set to 0:** deriveSide() resets these to 0 since the sim handles the underlying mechanics. These fields exist for the old custom StatusEngine and are no longer meaningful. No downstream consumers rely on the specific counter values (AnimationEngine reads TurnLogEntry, not these fields).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] filterSplitLines() added to handle |split| protocol duplicates**

- **Found during:** Task 2 (SimBattleAdapter implementation + smoke test)
- **Issue:** The battle's `send('update', ...)` callback receives raw log including `|split|p1`/`|split|p2` markers that produce DUPLICATE lines per event (one absolute HP line per player side, one shared percentage line). LogParser would emit 2-3 duplicate TurnLogEntry items per move. Initial smoke test showed `log.length = 0` because all lines were filtered as `||` empty lines.
- **Fix:** Added `filterSplitLines()` helper that strips `|split|pX` markers and the immediately following "secret" line, keeping only the "shared" line that is the canonical protocol representation.
- **Files modified:** src/battle/SimBattleAdapter.ts
- **Verification:** Smoke test shows correct unique TurnLogEntry items (1 DAMAGE per move, no duplicates)
- **Committed in:** b6fa82e (Task 2 commit)
