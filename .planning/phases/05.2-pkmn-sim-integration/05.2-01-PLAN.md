  <name>Task 1: Create LogParser for PS protocol to TurnLogEntry conversion</name>
  <files>src/battle/LogParser.ts</files>
  <action>
Create `src/battle/LogParser.ts` that exports `parseLogLines(lines: string[]): TurnLogEntry[]`.

This function takes the raw PS protocol lines collected from the Battle's `send` callback and converts them into our existing `TurnLogEntry[]` format. The TurnLogEntry kinds that downstream consumers (AnimationEngine, turnResultRenderer) use are: DAMAGE, MISS, FAINT, STATUS_INFLICT, STATUS_TICK, SWITCH, TERA, WIN, LOSS, PARALYSIS_SKIP, FROZEN, ASLEEP.

Note: PP_OUT is NOT emitted by LogParser. The sim does not produce a protocol line for PP depletion. PP tracking is handled by SimBattleAdapter via `simMon.moveSlots[i].pp` — if a move reaches 0 PP, the sim simply marks it as disabled in the next ChoiceRequest. If a PP_OUT TurnLogEntry is needed in the future, it can be synthesized in SimBattleAdapter by diffing ppUsed between turns.

**Protocol line parsing rules** (from research):

Each line starts with `|` and has `|`-delimited fields. Split on `|` — index 0 is empty, index 1 is the command.

Pokemon identifiers (POKEMON field) have format `p1a: Pikachu` or `p2a: Pikachu`. Actor is `'player'` if starts with `p1`, `'opponent'` if starts with `p2`. Extract pokemon name from after `: `.

Parse these commands:

1. `|move|POKEMON|MOVE|TARGET` — Set pendingMoveActor and pendingMoveName. Do NOT emit a log entry yet (wait for the damage/miss line that follows).

2. `|-damage|POKEMON|HP_STATUS` — Emit DAMAGE entry. Actor is pendingMoveActor (the attacker, not the target). Detail: `{ move: pendingMoveName, damage: 0, isCrit: false, targetHp: parsedHp, targetMaxHp: parsedMaxHp }`. Parse HP_STATUS: split on space to remove status suffix, then split on `/` for `cur/max`. Note: we set damage to 0 here — SimBattleAdapter will fill in real damage from sim state. Clear pendingMoveActor after.

3. `|-damage|POKEMON|HP_STATUS|[from] ...` — Same as above but the `[from]` tag indicates residual damage (status tick, hazards, etc.). If `[from]` contains "brn", "psn", "tox", or "Recoil", emit STATUS_TICK instead of DAMAGE. Actor is the pokemon being damaged (not the move user).

4. `|-miss|SOURCE|TARGET` — Emit MISS. Actor is the source (pendingMoveActor). Detail: `{ move: pendingMoveName }`. Clear pendingMoveActor.

5. `|faint|POKEMON` — Emit FAINT. Actor is the side of the fainted pokemon. Detail: `{ pokemon: extractedName }`.

6. `|-status|POKEMON|STATUS` — Emit STATUS_INFLICT. Actor is the side of the pokemon receiving the status. Detail: `{ pokemon: extractedName, status: statusString }`.

7. `|switch|POKEMON|DETAILS|HP_STATUS` or `|drag|POKEMON|DETAILS|HP_STATUS` — Emit SWITCH. Actor is the side switching. Detail: `{ pokemon: extractedName, fromIndex: 0, toIndex: 0 }`. Note: fromIndex/toIndex are set to 0 as placeholders — SimBattleAdapter fills them with real values from sim state.

8. `|-terastallize|POKEMON|TYPE` — Emit TERA. Actor is the side terastallizing. Detail: `{ teraType: typeString, pokemon: extractedName }`.

9. `|win|PLAYER` — Emit WIN if player name is `'Player'`, LOSS if `'Opponent'`. Actor accordingly. Detail: `{}`.

10. `|cant|POKEMON|REASON` — Check reason:
    - If reason contains "par" → emit PARALYSIS_SKIP
    - If reason contains "frz" → emit FROZEN
    - If reason contains "slp" → emit ASLEEP
    Actor is the pokemon's side. Detail: `{ pokemon: extractedName }`.

11. `|-crit|POKEMON` — Set a `pendingCrit = true` flag. When the next DAMAGE entry is emitted, set `isCrit: true` in the detail.

**Helper functions:**
- `pokemonToActor(ident: string): 'player' | 'opponent'` — returns 'player' if ident starts with 'p1', else 'opponent'
- `extractName(ident: string): string` — returns the part after ': ' (e.g., 'p1a: Pikachu' -> 'Pikachu')

**Anti-patterns:**
- Do NOT parse HP values from log strings for state derivation — that is SimBattleAdapter's job reading from `pokemon.hp`/`pokemon.maxhp` directly. The HP values in log lines are only used for the `targetHp`/`targetMaxHp` detail fields in DAMAGE entries (used by AnimationEngine for HP drain animation).
- Do NOT try to track cumulative state — LogParser is stateless across turns. It only tracks pendingMoveActor/pendingMoveName within a single parse call.

Create `src/battle/SimBattleAdapter.ts` that exports a module singleton `SimBattleAdapter` with the same API shape as `BattleEngine`, plus a `getBattle()` accessor for consumers that need the live Battle instance (e.g., SimAIOpponent):

```typescript
export const SimBattleAdapter = {
  startBattle(): BattleState { ... },
  submitAction(state: BattleState, playerAction: PlayerAction, opponentAction: PlayerAction): TurnResult { ... },
  submitSwitch(state: BattleState, side: 'player' | 'opponent', toIndex: number, aiSwitchIndex?: number): TurnResult { ... },
  getBattle(): Battle | null { return battle; },
} as const;
```

`getBattle()` returns the internal module-scope `battle` instance (or null before startBattle is called). This is needed by Plan 03 (ScreenController) to pass the live Battle to SimAIOpponent.

`submitSwitch()` accepts an optional `aiSwitchIndex` parameter for double-faint scenarios where both sides must switch in a single `makeChoices()` call. When provided, the adapter sends `switch ${toIndex + 1}` for the player side and `switch ${aiSwitchIndex + 1}` for the opponent side. When omitted (single-side switch), the other side's choice is `pass`.

**Internal state:** The adapter holds a mutable `battle: Battle | null` instance at module scope. This is NOT in the BattleState — it is internal to the adapter. The adapter also holds `logBuffer: string[]` to collect protocol lines and `prevHp: Map<string, number>` to track HP for damage calculation.

**Import strategy:**
```typescript
import { Battle, Teams, Dex } from '@pkmn/sim';
import { TeamGenerators } from '@pkmn/randoms';
```

Call `Teams.setGeneratorFactory(TeamGenerators)` at module scope (top level, runs once).

**startBattle() implementation:**

1. Generate teams by calling `TeamGenerators.getTeamGenerator('[Gen 9] Random Battle').getTeam()` directly to get `PokemonSet[]` for each side. Call it twice — once for player (`p1Sets`), once for opponent (`p2Sets`). The same `PokemonSet[]` is used for both `Teams.pack()` (passed to the sim) and for building the `BattlePokemon[]` arrays that populate `BattleState`.
2. Convert each `PokemonSet[]` to our `BattlePokemon[]` format for the BattleState team arrays. For each PokemonSet, compute the same fields that `TeamGenerator.buildRandom()` currently produces: `{ name, species, calcSpecies, level, ability, item, nature, gender, teraType, moves, evs, ivs, stats, currentHp, status, fainted, ppUsed, teraActive }`. Compute `stats` using `Dex.species.get(species).baseStats` + nature/evs/ivs formulas (or reuse the stat calc logic from TeamGenerator). Set `currentHp = stats.hp`, `status = ''`, `fainted = false`, `ppUsed = {}`, `teraActive = false`. This does NOT modify TeamGenerator.ts — it replicates the conversion inline in the adapter.
3. Create the Battle instance:
   ```typescript
   logBuffer.length = 0;
   battle = new Battle({
     formatid: 'gen9randombattle' as any,
     send(type: string, data: string) {
       if (type === 'update') {
         logBuffer.push(...data.split('\n').filter(l => l.length > 0));
       }
     },
   });
   ```
   NOTE: Pass `Dex` as second argument if required by the constructor signature. Check the actual constructor — it may be `new Battle(options)` without Dex, or `new Battle(options, Dex)`. The research says `new Battle({...}, Dex)`.
4. Set both players:
   ```typescript
   battle.setPlayer('p1', { name: 'Player', team: Teams.pack(p1Sets) });
   battle.setPlayer('p2', { name: 'Opponent', team: Teams.pack(p2Sets) });
   battle.sendUpdates();
   ```
5. Build initial BattleState from BattlePokemon arrays using `initActivePokemon()` — exactly like the current BattleEngine.startBattle() does. Return with phase WAITING_FOR_ACTION, turnCount 0, winner null.
6. Store the HP mapping: for each pokemon on both sides, record `prevHp[identKey] = pokemon.hp` where identKey is `'p1-${index}'` or `'p2-${index}'`.

**submitAction() implementation:**

1. Validate phase is WAITING_FOR_ACTION.
2. Translate playerAction to PS choice string using `actionToChoice(playerAction, battle!.sides[0]!)`.
3. The opponentAction also needs translation: `actionToChoice(opponentAction, battle!.sides[1]!)`.
4. Clear logBuffer.
5. Call `battle!.makeChoices(p1Choice, p2Choice)`.
6. Call `battle!.sendUpdates()`.
7. Parse logBuffer via `parseLogLines(logBuffer)` to get TurnLogEntry[].
8. Derive new BattleState from sim state using `deriveBattleState()`.
9. Fill in real damage values in the TurnLogEntry DAMAGE entries by comparing prevHp with current pokemon.hp values.
10. Update prevHp map.
11. Handle force-switch: if `battle.sides[0].activeRequest?.forceSwitch` or `battle.sides[1].activeRequest?.forceSwitch`, set phase to WAITING_FOR_SWITCH.
12. Return `{ nextState, log }`.

**submitSwitch() implementation:**

1. Validate phase is WAITING_FOR_SWITCH.
2. Build choice strings for BOTH sides. The player side gets `switch ${toIndex + 1}`. The opponent side:
   - If `aiSwitchIndex` is provided (double-faint case), send `switch ${aiSwitchIndex + 1}` for the opponent.
   - If `aiSwitchIndex` is NOT provided (single-side switch), check `battle.sides[otherIdx].activeRequest?.wait` — if true, that side should `pass`. If it has `forceSwitch`, stay in WAITING_FOR_SWITCH (caller handles separately).
   - `battle.makeChoices()` requires BOTH sides to submit. The non-switching side's choice is always `pass`.
3. Clear logBuffer, call makeChoices, sendUpdates.
4. Parse log, derive state.
5. After the switch, check if the battle is now WAITING_FOR_ACTION, WAITING_FOR_SWITCH (other side still needs switch), or BATTLE_OVER.
6. Return `{ nextState, log }`.

**actionToChoice() helper** (from research Pattern 3):
```typescript
function actionToChoice(action: PlayerAction, side: Side): string {
  if (action.type === 'SWITCH') {
    return `switch ${action.toIndex + 1}`;
  }
  const request = side.activeRequest;
  if (!request || !('active' in request) || !request.active?.[0]) {
    return 'move 1';
  }
  const moveIdx = request.active[0].moves.findIndex(m => m.id === action.moveSlug);
  const slot = moveIdx >= 0 ? moveIdx + 1 : 1;
  if (action.type === 'TERA_ATTACK') {
    return `move ${slot} terastallize`;
  }
  return `move ${slot}`;
}
```

**deriveBattleState() helper** (from research Pattern 2):

Read from `battle.sides[0]` and `battle.sides[1]` to populate BattleSide for player and opponent. For each pokemon in `side.pokemon`:
- `currentHp` = `simMon.hp`
- `status` = `simMon.status as StatusCondition` or `''`
- `fainted` = `simMon.fainted`
- `teraActive` = `!!simMon.terastallized` (cast with `(simMon as any).terastallized` if TS doesn't see the field)
- `ppUsed` = derive from `simMon.moveSlots`: for each slot, `ppUsed[slot.id] = slot.maxpp - slot.pp`
- Keep all other BattlePokemon fields from the original team data (name, species, calcSpecies, moves, teraType, level, ability, item, nature, gender, evs, ivs, stats)

For `activeIndex`: `side.pokemon.indexOf(side.active[0]!)` — fallback to 0 if active[0] is null.
For `teraUsed`: `side.pokemon.some(mon => !!(mon as any).terastallized)`.
For `turnCount`: `battle.turn`.
For `phase`: use `derivePhase()` from research.
For `winner`: if `battle.ended`, compare `battle.winner` with `'Player'` (p1 name).

**Key fields to preserve from original BattlePokemon:**
The adapter must store the original `BattlePokemon[]` arrays from team generation (playerTeamData, opponentTeamData) and spread those base fields into each ActivePokemon when deriving state. The sim's Pokemon objects do not have our custom fields (calcSpecies, stats table in our format, etc.).

**Anti-patterns to avoid:**
- Do NOT use BattleStream or getPlayerStreams — they require Node Buffer.
- Do NOT call `battle.start()` — it auto-starts when both players are set.
- Do NOT read HP from log strings — read from `pokemon.hp` and `pokemon.maxhp`.
- Do NOT mutate BattleState — always create new objects via spread.
- Do NOT hold references to sim Pokemon objects across turns — always copy values out.
