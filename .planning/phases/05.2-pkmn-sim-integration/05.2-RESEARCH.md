# Phase 5.2: @pkmn/sim Integration — Research

**Researched:** 2026-02-27
**Domain:** @pkmn/sim Battle API, protocol stream parsing, BattleState mapping
**Confidence:** HIGH — all findings sourced from installed package source code at node_modules/@pkmn/sim@0.10.6

---

## Summary

@pkmn/sim 0.10.6 is already installed as a transitive dependency of @pkmn/randoms, and the Dex class from it is already imported and working in the browser (TeamGenerator.ts uses `Dex.species.get()`). The Battle class is fully synchronous — `battle.makeChoices()` runs the entire turn and updates state in one synchronous call with no async boundary. The `@pkmn/streams` layer (used by `BattleStream` and `getPlayerStreams`) does use Node's `Buffer`, but the core `Battle` class has zero Buffer references. This means we use the `Battle` class directly — no stream layer needed — and avoid any polyfill requirement entirely.

The recommended architecture is a thin `SimBattleAdapter` wrapper around `Battle` that: (1) creates and holds a mutable `Battle` instance, (2) translates `PlayerAction` choices into PS choice strings, (3) calls `battle.makeChoices(p1choice, p2choice)` synchronously, (4) reads the updated `battle.sides[0|1].pokemon` array to derive a new `BattleState`, and (5) parses `battle.log` entries emitted since the last turn into `TurnLogEntry` items. The existing `BattleState`, `ActivePokemon`, `TurnLogEntry`, and `PlayerAction` types are kept unchanged — only `BattleEngine.ts` and `AIOpponent.ts` are replaced.

Team generation continues via `@pkmn/randoms` exactly as today. `Teams.pack()` converts the `PokemonSet[]` to a packed string, which is passed to `battle.setPlayer()`. For `gen9randombattle` format (no team preview), the battle starts immediately after both players are set.

**Primary recommendation:** Replace BattleEngine with a `SimBattleAdapter` that uses `Battle` directly (no BattleStream), calling `battle.makeChoices()` synchronously and deriving `BattleState` from `battle.sides[n].pokemon[*]` after each turn. Use `RandomPlayerAI.receiveRequest()` adapted to work without the stream, or just implement the AI choice directly using `battle.sides[1].activeRequest` to read the `ChoiceRequest` and build the choice string.

### Pattern 1: Direct Battle Creation (No Streams)

**What:** Instantiate `Battle` directly with a `send` callback that collects protocol log lines. After `makeChoices()`, read from `battle.sides[n].pokemon` for state and parse the collected log for `TurnLogEntry` items.

**Why not streams:** `BattleStream` + `getPlayerStreams` requires `@pkmn/streams` which uses Node's `Buffer`. The core `Battle` class has zero Buffer references and works in the browser already (Dex is already imported from @pkmn/sim in TeamGenerator.ts).

**Example:**

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/battle.js (constructor, makeChoices, setPlayer)
import { Battle, Teams, Dex } from '@pkmn/sim';
import { TeamGenerators } from '@pkmn/randoms';

// Step 1: Set up TeamGenerators (done once at module init)
Teams.setGeneratorFactory(TeamGenerators);

// Step 2: Generate teams via @pkmn/randoms (unchanged from current TeamGenerator.ts)
const generator = TeamGenerators.getTeamGenerator('gen9randombattle');
const p1Sets = generator.getTeam();   // PokemonSet[]
const p2Sets = generator.getTeam();   // PokemonSet[]

// Step 3: Create Battle with a log collector send callback
const logLines: string[] = [];
const battle = new Battle(
  {
    formatid: 'gen9randombattle',
    send: (type: string, data: string) => {
      if (type === 'update') {
        logLines.push(...data.split('\n').filter(l => l.startsWith('|')));
      }
      // 'sideupdate' delivers |request| JSON — extract per side if needed
    }
  },
  Dex
);

// Step 4: Register players — battle auto-starts when both are set (no team preview)
// Teams.setGeneratorFactory must be called first since gen9randombattle has team:'random'
// but we can also pass our own packed team to bypass sim's random generation
battle.setPlayer('p1', { name: 'Player', team: Teams.pack(p1Sets) });
battle.setPlayer('p2', { name: 'Opponent', team: Teams.pack(p2Sets) });
// battle.started === true at this point, turn 1 request emitted

// Step 5: Each turn — collect log, make choices, read updated state
logLines.length = 0; // reset for this turn
battle.makeChoices('move 1', 'move 2'); // p1 choice, p2 choice
battle.sendUpdates();
// logLines now contains |move|, |damage|, |-status|, |faint|, etc. for this turn
// battle.sides[0].pokemon[*] reflects updated HP, status, fainted state
```

### Pattern 2: Reading Battle State

**What:** Map `battle.sides[n]` to our existing `BattleState` type after each `makeChoices()` call.

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/pokemon.d.ts, side.d.ts
function deriveActivePokemon(pkmnSim: Pokemon, original: ActivePokemon): ActivePokemon {
  return {
    ...original,           // keeps name, species, moves, teraType, level, ability, item, etc.
    currentHp: pkmnSim.hp,
    status: (pkmnSim.status as StatusCondition) || '',
    fainted: pkmnSim.fainted,
    teraActive: !!pkmnSim.terastallized,  // 'terastallized' field on Pokemon, set after tera
    // ppUsed: must track separately — sim's MoveSlot has pp/maxpp
    ppUsed: buildPPUsed(pkmnSim),
  };
}

function buildPPUsed(pkmnSim: Pokemon): Record<string, number> {
  const ppUsed: Record<string, number> = {};
  for (const slot of pkmnSim.moveSlots) {
    ppUsed[slot.id] = slot.maxpp - slot.pp;
  }
  return ppUsed;
}

function deriveBattleState(battle: Battle, prevState: BattleState): BattleState {
  const p1 = battle.sides[0];
  const p2 = battle.sides[1];
  return {
    phase: battle.ended
      ? 'BATTLE_OVER'
      : (p1.activeRequest?.forceSwitch || p2.activeRequest?.forceSwitch)
        ? 'WAITING_FOR_SWITCH'
        : 'WAITING_FOR_ACTION',
    playerSide: {
      ...prevState.playerSide,
      team: p1.pokemon.map((simMon, i) =>
        deriveActivePokemon(simMon, prevState.playerSide.team[i]!)
      ),
      activeIndex: p1.active[0] ? p1.pokemon.indexOf(p1.active[0]) : prevState.playerSide.activeIndex,
      teraUsed: p1.pokemon.some(mon => !!mon.terastallized),
    },
    opponentSide: {
      ...prevState.opponentSide,
      team: p2.pokemon.map((simMon, i) =>
        deriveActivePokemon(simMon, prevState.opponentSide.team[i]!)
      ),
      activeIndex: p2.active[0] ? p2.pokemon.indexOf(p2.active[0]) : prevState.opponentSide.activeIndex,
      teraUsed: p2.pokemon.some(mon => !!mon.terastallized),
    },
    turnCount: battle.turn,
    winner: battle.ended
      ? (battle.winner === p1.name ? 'player' : 'opponent')
      : null,
  };
}
```

### Pattern 3: Choice String Translation

**What:** Convert our `PlayerAction` discriminated union to PS choice strings.

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/side.js (choose() parsing)
// Terastallize: append ' terastallize' (or ' terastal') to the move string
// Switch: 'switch SLOT' where SLOT is 1-based position in team

function actionToChoiceString(
  action: PlayerAction,
  side: Side,           // battle.sides[0] or battle.sides[1]
): string {
  if (action.type === 'SWITCH') {
    // action.toIndex is 0-based; PS switch uses 1-based team slot
    return `switch ${action.toIndex + 1}`;
  }

  // Find 1-based move slot from moveSlug
  const activeRequest = side.activeRequest as MoveRequest;
  const moveIdx = activeRequest?.active?.[0]?.moves.findIndex(
    m => m.id === action.moveSlug
  ) ?? -1;
  const slot = moveIdx >= 0 ? moveIdx + 1 : 1; // fallback to slot 1

  if (action.type === 'TERA_ATTACK') {
    return `move ${slot} terastallize`;
  }
  return `move ${slot}`;
}
```

### Pattern 4: Log Parsing → TurnLogEntry

**What:** Parse the PS protocol messages in `battle.log` into our `TurnLogEntry` format.

```typescript
// Source: WebFetch https://raw.githubusercontent.com/smogon/pokemon-showdown/master/sim/SIM-PROTOCOL.md
// Key protocol messages:
//   |move|POKEMON|MOVE|TARGET         → kind: 'DAMAGE' (paired with |-damage|)
//   |-damage|POKEMON|CUR/MAX STATUS   → kind: 'DAMAGE'
//   |-miss|POKEMON|TARGET             → kind: 'MISS'
//   |faint|POKEMON                    → kind: 'FAINT'
//   |-status|POKEMON|STATUS           → kind: 'STATUS_INFLICT'
//   |-damage|POKEMON|HP [from status] → kind: 'STATUS_TICK'
//   |switch|POKEMON|DETAILS|HP STATUS → kind: 'SWITCH'
//   |-terastallize|POKEMON|TYPE       → kind: 'TERA'
//   |win|USER                         → kind: 'WIN' or 'LOSS'

function parseLogLines(lines: string[], p1Name: string, p2Name: string): TurnLogEntry[] {
  const entries: TurnLogEntry[] = [];
  let pendingMoveActor: 'player' | 'opponent' | null = null;
  let pendingMoveName: string | null = null;

  for (const line of lines) {
    const parts = line.split('|');
    if (parts.length < 2) continue;
    const cmd = parts[1];

    switch (cmd) {
      case 'move': {
        // |move|POKEMON|MOVE|TARGET
        const actor = pokemonToActor(parts[2]!, p1Name);
        pendingMoveActor = actor;
        pendingMoveName = parts[3] ?? '';
        break;
      }
      case '-damage': {
        // |‐damage|POKEMON|HP STATUS
        // Parse 'CUR/MAX' or 'CUR/100' format
        const target = parts[2]!;
        const actor = pendingMoveActor ?? pokemonToActor(target, p1Name);
        const [curStr, maxStr] = (parts[3] ?? '').split('/');
        const damage = /* derive from prevState HP - curHP */;
        entries.push({ kind: 'DAMAGE', actor, detail: { move: pendingMoveName, damage, isCrit: false, targetHp: Number(curStr), targetMaxHp: Number(maxStr) } });
        pendingMoveActor = null;
        break;
      }
      case '-miss':
        entries.push({ kind: 'MISS', actor: pendingMoveActor ?? 'player', detail: { move: pendingMoveName } });
        pendingMoveActor = null;
        break;
      case 'faint':
        entries.push({ kind: 'FAINT', actor: pokemonToActor(parts[2]!, p1Name), detail: { pokemon: extractName(parts[2]!) } });
        break;
      case '-status':
        entries.push({ kind: 'STATUS_INFLICT', actor: pokemonToActor(parts[2]!, p1Name), detail: { pokemon: extractName(parts[2]!), status: parts[3] } });
        break;
      case '-terastallize':
        entries.push({ kind: 'TERA', actor: pokemonToActor(parts[2]!, p1Name), detail: { teraType: parts[3], pokemon: extractName(parts[2]!) } });
        break;
      case 'win':
        const winnerIsPlayer = parts[2] === p1Name;
        entries.push({ kind: winnerIsPlayer ? 'WIN' : 'LOSS', actor: winnerIsPlayer ? 'player' : 'opponent', detail: {} });
        break;
    }
  }
  return entries;
}

function pokemonToActor(ident: string, p1Name: string): 'player' | 'opponent' {
  // ident format: 'p1: Pikachu' or 'p1a: Pikachu'
  return ident.startsWith('p1') ? 'player' : 'opponent';
}
function extractName(ident: string): string {
  // 'p1: Pikachu' → 'Pikachu'
  return ident.split(': ')[1] ?? ident;
}
```

### Pattern 5: AI Opponent Using ChoiceRequest

**What:** The opponent AI reads `battle.sides[1].activeRequest` to know what moves are available, then picks a choice string. This replaces `AIOpponent.pickAction()`.

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/tools/random-player-ai.js
// The built-in RandomPlayerAI requires the stream layer (BattlePlayer extends it).
// Instead, extract just the choice-building logic:

function pickOpponentChoice(battle: Battle): string {
  const side = battle.sides[1]!;
  const request = side.activeRequest;
  if (!request || request.wait) return 'default';

  if (request.forceSwitch) {
    // Pick first available non-fainted switch
    const pokemon = request.side.pokemon;
    const canSwitch = pokemon
      .map((p, i) => ({ p, i }))
      .filter(({ p, i }) => i >= request.forceSwitch.length && !p.condition.endsWith(' fnt'));
    if (canSwitch.length > 0) {
      return `switch ${canSwitch[0]!.i + 1}`;
    }
    return 'pass';
  }

  if (request.active) {
    const active = request.active[0]!;
    // Pick first non-disabled move
    const moves = active.moves;
    const available = moves.filter(m => !m.disabled);
    if (available.length > 0) {
      const idx = moves.indexOf(available[0]!) + 1;
      return `move ${idx}`;
    }
    return 'move 1';
  }

  return 'default';
}
```

### Anti-Patterns to Avoid

- **Using BattleStream + getPlayerStreams:** This requires `@pkmn/streams` which uses Node's `Buffer`. Causes browser build failure. Use `Battle` directly.
- **Calling `Teams.generate()` without `Teams.setGeneratorFactory(TeamGenerators)` first:** The Teams module throws if no factory is set. Must call `Teams.setGeneratorFactory(TeamGenerators)` before any `Teams.generate()` or format-based team generation.
- **Passing `formatid: 'gen9custombattle'`:** Custom Game enables Team Preview (3-way selection), which adds a `teamPreview` request phase that requires handling `choose 123456` before the battle starts. Use `gen9randombattle` instead and pass teams directly via `Teams.pack()`.
- **Mutating `battle.sides[n].pokemon` objects:** Battle state is mutable in the sim. When deriving `BattleState`, always spread/copy values out — never hold references to `Pokemon` objects across turns.
- **Reading `battle.sides[n].active[0]` for team order:** `sides[n].active` only has the currently active Pokémon. The full team is `sides[n].pokemon`. Active index = `sides[n].pokemon.indexOf(sides[n].active[0])`.
- **Assuming `|‐damage|` HP values are absolute:** For the opponent's Pokémon, with `HP Percentage Mod` (which gen9randombattle has), HP is reported as percentages (e.g., `54/100`). For our own Pokémon it's absolute (e.g., `156/220`). Read HP from `battle.sides[n].pokemon[i].hp` and `maxhp` instead for reliable exact values.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Gen 9 damage rolls | Custom damage formula | `battle.makeChoices()` | Sim handles spread, crit, STAB, type, ability, item, terrain, weather — hundreds of edge cases |
| Priority / turn order | Custom speed/priority sort | `battle.makeChoices()` | Sim handles Quick Claw, Prankster, Trick Room, trickroom bracket ordering, etc. |
| Status conditions | Custom sleep/freeze/para logic | `battle.makeChoices()` | Sleep Clause Mod, status immunity via ability (e.g. Comatose), all handled |
| Terastallization mechanics | Custom Tera type change | `battle.makeChoices()` + `' terastallize'` suffix | Sim tracks one-use-per-battle, type change, STAB recalculation |
| Ability/item interactions | Hand-coded ability list | `battle.makeChoices()` | Thousands of ability/item interactions (Intimidate on switch-in, etc.) |
| Random AI | Heuristic scorer | Extract from RandomPlayerAI or implement directly using `side.activeRequest` | Built-in pattern handles all request types (move, switch, teampreview, wait) |
| Team packing | Custom team serialization | `Teams.pack(sets)` | Converts `PokemonSet[]` directly to the packed string format `setPlayer()` expects |

**Key insight:** The entire `DamageCalc.ts`, `StatusEngine.ts`, and `TurnResolver.ts` files should be deleted. The custom BattleEngine was doing ~40% of what the real sim does, getting the other 60% wrong. Every Pokemon interaction that required special-casing in those files is now handled correctly by the sim.

## Common Pitfalls

### Pitfall 1: HP Percentage Mode in gen9randombattle

**What goes wrong:** When parsing `|-damage|p2: Pokemon|45/100 brn` from the log, you might assume these are absolute HP values. They are percentages for the *opponent's* Pokémon under `HP Percentage Mod`.
**Why it happens:** gen9randombattle includes `HP Percentage Mod` in its ruleset, causing HP to be reported as percentages in log messages for the opponent.
**How to avoid:** Do not derive HP values from protocol log strings. After each `makeChoices()` call, read `battle.sides[n].pokemon[i].hp` and `battle.sides[n].pokemon[i].maxhp` directly — these are always exact integers.
**Warning signs:** Player Pokémon HP seems right but opponent always shows 0-100 range.

### Pitfall 2: Teams.setGeneratorFactory Must Be Called Before Battle Creation

**What goes wrong:** `Battle.setPlayer()` calls `battle.getTeam()` → `Teams.getGenerator()` which throws `Error: getTeamGenerator maybe not be used unless a TeamGeneratorFactory has been set` if called for a `team: 'random'` format before the factory is registered.
**Why it happens:** gen9randombattle has `team: 'random'` in its format definition. If you pass a packed team to `setPlayer()`, the factory is not needed. But if you ever call without a team, or if test code runs without setup, it throws.
**How to avoid:** Call `Teams.setGeneratorFactory(TeamGenerators)` once at module init (the same place TeamGenerator.ts already imports from @pkmn/randoms). Since we always pass packed teams, this mostly doesn't bite — but set it anyway for safety.
**Warning signs:** `Error: getTeamGenerator may not be used unless a TeamGeneratorFactory has been set`.

### Pitfall 3: Battle is Started Automatically When Both Players Set

**What goes wrong:** Calling `battle.start()` manually after `setPlayer('p1',...)` and `setPlayer('p2',...)` throws `Error: Battle already started`.
**Why it happens:** `setPlayer()` calls `this.start()` automatically once `this.sides.every(playerSide => !!playerSide)`. The battle starts, emits the turn 1 `|request|` JSON to each side via `send('sideupdate', ...)`.
**How to avoid:** Never call `battle.start()` manually. Just call `setPlayer()` for both players and then call `sendUpdates()` to flush the log and collect the initial requests.
**Warning signs:** `Error: Battle already started`.

### Pitfall 4: `sendUpdates()` Must Be Called to Flush the Log

**What goes wrong:** After `makeChoices()`, `battle.log` has new entries but `battle.sentLogPos` hasn't advanced. If you read `battle.log` directly and skip `sendUpdates()`, your log slice tracking gets out of sync on the next turn.
**Why it happens:** `sendUpdates()` calls `this.send('update', this.log.slice(this.sentLogPos))` and then advances `sentLogPos`. It also calls `side.emitRequest()` to send the next turn's request.
**How to avoid:** After every `makeChoices()` call, always call `battle.sendUpdates()`. Your `send` callback collects both the `update` (log lines) and `sideupdate` (next `|request|` JSON) messages.
**Warning signs:** Log parsing works turn 1 but gets stale or doubled on turns 2+.

### Pitfall 5: Force-Switch Requests After Faint

**What goes wrong:** After a Pokémon faints, the sim does NOT automatically switch in the next Pokémon. It emits a `forceSwitch: [true]` request. If you call `makeChoices()` again without handling the switch first, it fails or the game stalls.
**Why it happens:** The sim faithfully mirrors the game: the player must actively choose which Pokémon to send in. The request has `forceSwitch: [true]` for the side that needs to switch.
**How to avoid:** After `makeChoices()`, check `battle.sides[0].activeRequest?.forceSwitch` and `battle.sides[1].activeRequest?.forceSwitch`. Map this to `WAITING_FOR_SWITCH` phase in `BattleState`. The player choice is `switch N`, the AI also needs to make a switch choice.
**Warning signs:** `[Invalid choice] Can't move: You need to switch in a Pokemon to replace your fainted Pokemon!`

### Pitfall 6: Terastallize Choice String Format

**What goes wrong:** Sending `'move 1 tera'` or `'move 1 mega'` for terastallization.
**Why it happens:** The correct suffix is `' terastallize'` (or `' terastal'` as shorthand). From `side.js`: `data.endsWith(' terastallize')` or `data.endsWith(' terastal')`.
**How to avoid:** Use `'move ${slot} terastallize'`.
**Warning signs:** `[Invalid choice] Can't mega evolve: ...` or choice error.

### Pitfall 7: Move Slot Is 1-Based, Not Move ID

**What goes wrong:** Sending `'move thunderbolt'` instead of `'move 2'` for the second move.
**Why it happens:** The PS protocol for choices uses 1-based slot numbers, not move names/IDs. `'move thunderbolt'` is invalid.
**How to avoid:** Use `side.activeRequest` (the `MoveRequest` type) to look up the move's position in `request.active[0].moves`, then use `'move ${moveIndex + 1}'`.
**Warning signs:** `[Invalid choice] Can't move: ...` errors.

## Code Examples

### Full Battle Lifecycle

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/battle.js — constructor, setPlayer, makeChoices, sendUpdates
// Source: node_modules/@pkmn/randoms/README.md — Teams.setGeneratorFactory pattern
import { Battle, Teams, Dex } from '@pkmn/sim';
import { TeamGenerators } from '@pkmn/randoms';

// One-time setup at module init
Teams.setGeneratorFactory(TeamGenerators);

// Start a battle with two pre-generated teams
function createSimBattle(p1Sets: PokemonSet[], p2Sets: PokemonSet[]) {
  const logBuffer: string[] = [];
  const sideRequests: Record<string, string> = {};

  const battle = new Battle(
    {
      formatid: 'gen9randombattle',
      send(type: string, data: string) {
        if (type === 'update') {
          logBuffer.push(...data.split('\n').filter(l => l.length > 0));
        } else if (type === 'sideupdate') {
          const [side, sideData] = data.split('\n') as [string, string];
          sideRequests[side] = sideData;
        }
      },
    },
    Dex
  );

  // Passing packed team bypasses the sim's own random team generation
  battle.setPlayer('p1', { name: 'Player', team: Teams.pack(p1Sets) });
  battle.setPlayer('p2', { name: 'Opponent', team: Teams.pack(p2Sets) });
  battle.sendUpdates(); // flush initial log + emit turn 1 requests

  return { battle, logBuffer, sideRequests };
}

// Resolve one turn
function resolveTurn(
  battle: Battle,
  logBuffer: string[],
  p1Choice: string,
  p2Choice: string,
): string[] {
  logBuffer.length = 0; // reset collector
  battle.makeChoices(p1Choice, p2Choice);
  battle.sendUpdates();
  return [...logBuffer]; // return lines for this turn
}
```

### Reading State from Battle After Turn

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/pokemon.d.ts (hp, maxhp, status, fainted, terastallized, moveSlots)
// Source: node_modules/@pkmn/sim/build/cjs/sim/side.d.ts (pokemon[], active[], activeRequest)
function readSideState(side: Side, prevTeam: ActivePokemon[]): BattleSide {
  const activeSimMon = side.active[0];
  const activeIndex = activeSimMon
    ? side.pokemon.indexOf(activeSimMon)
    : 0;

  const team = side.pokemon.map((simMon, i) => {
    const prev = prevTeam[i]!;
    const ppUsed: Record<string, number> = {};
    for (const slot of simMon.moveSlots) {
      ppUsed[slot.id] = slot.maxpp - slot.pp;
    }
    return {
      ...prev,
      currentHp: simMon.hp,
      status: (simMon.status as StatusCondition) || '',
      fainted: simMon.fainted,
      teraActive: !!simMon.terastallized,
      ppUsed,
    } satisfies ActivePokemon;
  });

  return {
    team,
    activeIndex,
    teraUsed: team.some(mon => mon.teraActive),
  };
}
```

### Deriving Phase and Winner

```typescript
// Source: node_modules/@pkmn/sim/build/cjs/sim/battle.d.ts (ended, winner, turn)
// Source: node_modules/@pkmn/sim/build/cjs/sim/side.d.ts (activeRequest, ChoiceRequest)
function derivePhase(battle: Battle): BattlePhase {
  if (battle.ended) return 'BATTLE_OVER';

  const p1NeedsSwitch = battle.sides[0]?.activeRequest?.forceSwitch?.some(Boolean);
  const p2NeedsSwitch = battle.sides[1]?.activeRequest?.forceSwitch?.some(Boolean);
  if (p1NeedsSwitch || p2NeedsSwitch) return 'WAITING_FOR_SWITCH';

  return 'WAITING_FOR_ACTION';
}

function deriveWinner(battle: Battle, p1Name: string): 'player' | 'opponent' | null {
  if (!battle.ended) return null;
  return battle.winner === p1Name ? 'player' : 'opponent';
}
```

```typescript
function actionToChoice(action: PlayerAction, side: Side): string {
  const request = side.activeRequest;

  if (action.type === 'SWITCH') {
    return `switch ${action.toIndex + 1}`;
  }

  if (!request || !('active' in request) || !request.active?.[0]) {
    return 'move 1';
  }

  const moveRequest = request.active[0];
  const moveIdx = moveRequest.moves.findIndex(m => m.id === action.moveSlug);
  const slot = moveIdx >= 0 ? moveIdx + 1 : 1;

  if (action.type === 'TERA_ATTACK') {
    return `move ${slot} terastallize`;
  }
  return `move ${slot}`;
}
```

```typescript
function pickAIChoice(battle: Battle): string {
  const side = battle.sides[1]!;
  const request = side.activeRequest;

  if (!request || request.wait) return '';

  if (request.forceSwitch) {
    const pokemon = request.side.pokemon;
    const mustSwitch = request.forceSwitch[0];
    if (!mustSwitch) return 'pass';

    // Find first alive non-active Pokémon (1-based slot)
    const slot = pokemon.findIndex(
      (p, i) => i >= request.forceSwitch.length && !p.condition.endsWith(' fnt')
    );
    return slot >= 0 ? `switch ${slot + 1}` : 'pass';
  }

  if (request.active?.[0]) {
    const active = request.active[0];
    // Pick first non-disabled move
    const moveIdx = active.moves.findIndex(m => !m.disabled);
    const slot = moveIdx >= 0 ? moveIdx + 1 : 1;
    return `move ${slot}`;
  }

  return 'move 1';
}
```

## Open Questions

1. **HP percentage parsing in log vs. direct field read**
   - What we know: gen9randombattle includes `HP Percentage Mod` — log messages show opponent HP as percentages, not absolute values
   - What's unclear: Whether `battle.sides[1].pokemon[i].hp` always reflects exact absolute HP or if HP Percentage Mod affects the in-memory field too
   - Recommendation: Read HP from `pokemon.hp` and `pokemon.maxhp` fields, NOT from log strings. The `reportExactHP` Battle property (set to `true` in debug mode) controls log output only, not in-memory fields. **Confidence: MEDIUM** — log parsing for HP should be skipped; use direct field reads.

2. **winner field format on Battle**
   - What we know: `battle.winner` is set when `battle.ended === true`. Type is `string | undefined` per declarations.
   - What's unclear: Is it the player's `name` string (e.g., `'Player'`) or the side ID (`'p1'`)?
   - Recommendation: Check `battle.winner === battle.sides[0].name` to determine if p1 won. Fallback: check if all of `sides[1].pokemon` are fainted.
   - **Confidence: MEDIUM** — based on code reading, winner is the player name string from `side.name`.

3. **Terastallized field name on Pokemon**
   - What we know: `Pokemon` has a `terastallized` field (seen in battle.js: `delete pokemon.terastallized`). But the TypeScript declaration for it isn't in the exported `pokemon.d.ts`.
   - What's unclear: The exact TypeScript-visible field name — it may be a volatile or a condition rather than a direct boolean field.
   - Recommendation: At implementation time, check `pokemon.volatiles['typechange']` or `pokemon.terastallized` in the live battle object. Cast with `(simMon as any).terastallized` if needed. **Confidence: LOW** — needs runtime verification.

4. **How to handle the initial team preview skip**
   - What we know: gen9randombattle has no Team Preview ruleset entry, so `runPickTeam()` does not emit a `teampreview` request.
   - What's unclear: Whether any other pre-battle request phase occurs that we need to handle before turn 1.
   - Recommendation: After `setPlayer()` for both sides + `sendUpdates()`, check `sides[0].activeRequest` — it should be a `MoveRequest` (turn 1 move selection). If it's null or `wait`, call `sendUpdates()` again. **Confidence: HIGH**.
