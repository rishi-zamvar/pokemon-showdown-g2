## `runBattleScript()` is a reusable export, not a private scenario body

The ROADMAP names `runBattleScript()` in the Phase 12 assertion vocabulary and then
builds Phases 13, 14, 17 and 19 on it — "`expectConsoleClean()` across
`runBattleScript()`", "`expectRegionPersists(...)` over `runBattleScript()`",
"golden-frame diffs captured at fixed turns inside `runBattleScript()`", "wall-clock
per screen change recorded across `runBattleScript()`". Exporting only
`battleScenario: Scenario` would force each of those phases to fork this file. So the
battle is a parameterised exported function with an `onTurn` hook, and `battleScenario`
is a thin default wrapper around it (B7).

## Navigation map (read from src this session -- do not re-derive)

```
MAIN_MENU        [0] Enter Battle   [1] Battle Speed: <preset>   [2] About/Credits
                 item 1 CYCLES the preset in place and re-renders with cursor=1
                 cycle order: Normal -> Fast -> Instant -> Slow  (starts at Normal)
BATTLE_HUD       [0] Attack   [1] Switch   [2] Terastallize   [3] Stats (no-op)
ATTACK_SELECT    move list, index 0 = first move, no "< Back" (removed in Phase 9)
SWITCH_SELECT    team list; when forced, status reads "MUST SWITCH" and double-tap is blocked
TURN_RESULT      requires ONE tap to advance; then routes by battle phase:
                 WAITING_FOR_ACTION -> BATTLE_HUD
                 WAITING_FOR_SWITCH -> SWITCH_SELECT (forced, after a faint)
                 BATTLE_OVER        -> END_SCREEN
END_SCREEN       [0] New Battle   [1] Main Menu
```

## Screen waits must be watermarked (B4)

`ctx.logs.reset()` happens once per `ctx.step()`, and a whole turn is one step, so the
console buffer still holds the `[screen] BATTLE_HUD` line from the top of the turn when
the end-of-turn wait runs. A substring scan over `logs.all()` therefore returns
BATTLE_HUD immediately and unconditionally: `sawForcedSwitch` and `finished` would never
become true and the `end-screen` / `coverage` steps would fail on every run. Every wait
in this file takes a `const from = ctx.logs.nextSeq()` watermark captured BEFORE the
input that should cause the transition, and considers only lines with `seq >= from`.

## Why the script sets Instant speed first

At Normal speed a turn costs the typewriter (~45 ms/char), a 500 ms pause per log
entry, and ~477 ms per screen change -- a 30-turn battle would run 10+ minutes and
make the suite something nobody runs. Two clicks on main-menu item 1 cycles
Normal -> Fast -> Instant, which skips animation entirely (`SpeedConfig.multiplier()`
returns 0). This is a real user path, not a test hook.

That is also why animation-frame assertions are NOT in this plan: Phase 14 owns
`expectRegionPersists` across animation frames and will run its own scenario at a
non-Instant speed.

```typescript
export interface BattleScriptOpts {
  speed?: "Normal" | "Fast" | "Instant";   // default "Instant"
  maxTurns?: number;                        // default 60
```

    ```ts
     * Wait until the app logs any one of `names` AT OR AFTER the `from` watermark.
     * Returns whichever won. `from` is REQUIRED -- see B4 in the objective.
     */
    async function waitAnyScreen(
      ctx: Ctx, names: ScreenName[], from: number, timeoutMs = 25_000,
    ): Promise<ScreenName>
    ```
    implemented with `waitFor`: poll `ctx.logs.poll()`, then scan
    `ctx.logs.all().filter(l => l.seq >= from)` for `[screen] <name>` and return the
    first match, else null. Needed because after a move resolves the app may route to
    BATTLE_HUD, SWITCH_SELECT (forced) or END_SCREEN and the harness cannot know which
    in advance. Making `from` a required positional parameter rather than a defaulted
    one is deliberate: the default would be wrong at exactly the call site that matters.

    Export `runBattleScript(ctx, opts)` returning `BattleOutcome` (B7). It performs the
    steps below and RETURNS the outcome rather than asserting coverage itself, so later
    phases can reuse it with different `opts`. Call `opts.onTurn?.(turn, ctx)` at the end
    of every turn iteration, inside that turn's `ctx.step`, so a caller's per-turn
    assertions are attributed to the right step.

    Then export `battleScenario: Scenario` (`needsSim: true`) as a thin wrapper:
    `const outcome = await runBattleScript(ctx)` followed by the `coverage` and
    `back-to-menu` steps described below.

    Steps, each wrapped in `ctx.step(...)` so the runner reports pass/fail and host-call
    counts per step (D-13, success criterion 5):

    1. `menu` -- `waitScreen("MAIN_MENU")`; `expectFrameInk(f, REGIONS.CONTENT, 0.01, 0.60)`;
       `expectConsoleClean(logs)`.
    2. `set-speed` -- no-op when `opts.speed === "Normal"` (the app's default on open).
       Otherwise `press("down")` (cursor 0 -> 1), then `press("click")` N times where N
       is the distance to `opts.speed` along the fixed cycle
       `Normal -> Fast -> Instant -> Slow` (Fast=1, Instant=2, Slow=3). Default
       `opts.speed` is `"Instant"`, i.e. two clicks. Phase 14 will call this with
       `"Normal"` to get real animation frames.
       Item 1 cycles the preset in place and re-renders with cursor=1. Take a watermark
       before each click and wait for a `[screen] MAIN_MENU cursor=1` line with
       `seq >= watermark` -- without it the second click's wait matches the first
       click's line and returns instantly (B4). `expectConsoleClean(logs)`.
       ponytail: click-count is derived from SpeedConfig's fixed cycle order and its
       Normal default on every app open. If that order changes this step fails loudly
       at the next step rather than silently running slow -- acceptable; the alternative
       is OCR on the framebuffer, which D-10 rules out.
    3. `enter-battle` -- `press("up")` (cursor 1 -> 0), `press("click")`;
       `waitScreen("BATTLE_HUD", 60_000)` -- team generation, match-data load and sprite
       fetches all happen here, so the timeout is deliberately generous.
       `expectFrameInk(f, REGIONS.LIST, 0.01, 0.60)` (the action list must have ink -- a
       blank list here is exactly defect #2 from the research doc, where an oversized
       container took the whole `rebuildPageContainer` down and left no action list).
       `expectFrameInk(f, REGIONS.PLAYER_COMPOSITE, 0.01, 0.95)` and the same for
       `OPP_COMPOSITE`. `expectConsoleClean(logs)`.
    4. `turn-N` loop, `for (let turn = 1; turn <= maxTurns; turn++)` with
       `maxTurns = opts.maxTurns ?? 60`. Track `sawVoluntarySwitch`, `sawForcedSwitch`,
       `finished`. Each iteration is its own `ctx.step(\`turn-${turn}\`, ...)`.
       **Every wait below takes a watermark captured immediately before the input that
       should cause it (B4)** -- `const w = ctx.logs.nextSeq()` then
       `await ctx.press(...)` then `await ctx.waitScreen(NAME, ms, w)`.
       - `waitScreen("BATTLE_HUD", 25_000, wTurnStart)` where `wTurnStart` was taken at
         the end of the previous iteration (or before `enter-battle`'s click on turn 1).
       - On `turn === (opts.switchOnTurn ?? 3)` and only if `!sawVoluntarySwitch`: do the
         VOLUNTARY SWITCH -- `press("down")` (cursor 0 -> 1 = Switch), watermark,
         `press("click")`, `waitScreen("SWITCH_SELECT", ..., w)`, `press("down")` (skip
         index 0, which may be the currently active Pokemon and would be an illegal
         choice), watermark, `press("click")`, `waitScreen("TURN_RESULT", ..., w)`.
         Reaching TURN_RESULT is the proof the switch was accepted; an illegal or dropped
         choice leaves the app on SWITCH_SELECT and the wait fails with a named timeout.
         Set `sawVoluntarySwitch = true`.
       - Otherwise ATTACK: watermark, `press("click")` (cursor 0 = Attack),
         `waitScreen("ATTACK_SELECT", ..., w)`,
         `expectFrameInk(f, REGIONS.LIST, 0.01, 0.60)`, watermark, `press("click")`
         (first move), `waitScreen("TURN_RESULT", 30_000, w)`.
       - Take `const wAfter = ctx.logs.nextSeq()`, `press("click")` to advance past
         TURN_RESULT, then
         `const next = await waitAnyScreen(ctx, ["BATTLE_HUD", "SWITCH_SELECT", "END_SCREEN"], wAfter)`.
         The watermark is load-bearing here: without it the `[screen] BATTLE_HUD` line
         from the top of this same step matches instantly, `next` is always
         `"BATTLE_HUD"`, and `sawForcedSwitch`/`finished` never become true (B4).
       - If `next === "SWITCH_SELECT"`: this is a FORCED switch after a faint (the script
         did not press Switch this iteration). Watermark, `press("click")` (cursor 0 =
         first alive), `waitAnyScreen(ctx, ["BATTLE_HUD", "TURN_RESULT", "END_SCREEN"], w)`,
         set `sawForcedSwitch = true`.
       - If `next === "END_SCREEN"`: set `finished = true`, record `turns = turn`, break.
       - Record `hostCallsByTurn[turn] = ctx.logs.hostCalls()` BEFORE the step ends
         (`ctx.step` resets the console on the NEXT step, so read it inside this one).
       - `await opts.onTurn?.(turn, ctx)` -- the extension point Phases 14/17/19 use.
       - `expectConsoleClean(logs)` last in every turn step -- HARN-05 must hold for every
         turn of a real battle, not just at boot. This is the assertion that catches a
         container-validation line appearing on turn 17.
    5. `end-screen` -- fail unless `finished`, with the message
       `` `battle did not reach END_SCREEN within ${maxTurns} turns` ``.
       `expectScreen(logs, "END_SCREEN")`; capture the frame as `end-screen.png`;
       `expectFrameInk(f, REGIONS.CONTENT, 0.01, 0.60)`; `expectConsoleClean(logs)`.
       This is the last step inside `runBattleScript`, which then returns `BattleOutcome`.
    6. `coverage` (in `battleScenario`, not in `runBattleScript`) -- assert
       `outcome.sawVoluntarySwitch` and `outcome.sawForcedSwitch`, each with its own
       message naming which half of HARN-04 was not exercised. A 6v6 randbats battle
       always produces faints before a winner, so a missing forced switch means the
       script never detected one, not that the battle had none. Kept out of
       `runBattleScript` so a Phase 14/17 caller can run a short
       `{ maxTurns: 5 }` battle without tripping coverage assertions it never intended.
    7. `back-to-menu` -- `press("down")`, `press("click")` (END_SCREEN item 1 = Main Menu),
       `waitScreen("MAIN_MENU")`, `expectConsoleClean(logs)`. Proves the loop closes and
       leaves the app in a re-runnable state.

    `[selfCheckScenario, bootScenario, negativeProofScenario, battleScenario]`.
    Turn-by-turn frames are already saved by `ctx.capture` inside `waitScreen` (D-09),
    so a failing turn leaves a viewable PNG in the run dir.
