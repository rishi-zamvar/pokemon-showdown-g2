<objective>
Build the framebuffer analysis primitives: a zero-dependency PNG decoder, ink/grey
metrics over named rectangles, and a region map derived from the app's own layout
constants.

Purpose: HARN-03 says a blank or malformed screen must FAIL a test. That is only
possible if the harness can read pixels. D-07 fixes the assertion primitive as ink
coverage per region and D-10 forbids golden-image diffing, so this plan delivers
exactly two metrics — ink ratio and distinct grey level count — and nothing more.

Output: `harness/` tree with png.ts, frame.ts, regions.ts, selfCheck.ts, tsconfig.json.

## Why a hand-rolled PNG decoder and not a dependency

The repo has no image library and adding one (`pngjs`, `sharp`, `jimp`) buys
generality this harness never uses. The only PNG that ever reaches this code is
the simulator's own `/api/screenshot/glasses` output: 8-bit, non-interlaced,
truecolour-with-alpha. Node ships `zlib.inflateSync` in stdlib, and the remaining
work is chunk-walking plus the five PNG scanline filters — roughly 70 lines.
`sharp` alone is a ~30 MB native binary for that.

The decoder therefore supports 8-bit non-interlaced colour types 0/2/4/6 and
**throws loudly** on anything else rather than guessing. If the simulator ever
emits a palette or 16-bit PNG the harness fails with a clear message instead of
silently reading garbage pixels.

## Runtime: no TS runner dependency either

Node 22.20 (verified in this environment) strips TypeScript types natively —
`node harness/selfCheck.ts` runs with no `tsx`, no `ts-node`, no build step, as
long as relative imports carry the `.ts` extension. `harness/tsconfig.json` sets
`allowImportingTsExtensions` + `noEmit` so `tsc` accepts the same import shape.

harness/png.ts:
```typescript
export interface DecodedPng {
  width: number;
  height: number;
  /** RGBA, 4 bytes per pixel, row-major, length = width * height * 4 */
  rgba: Uint8Array;
}
export function decodePng(buf: Uint8Array): DecodedPng;
```

harness/frame.ts:
```typescript
export interface Region {
  name: string;
  x: number;
  y: number;
  w: number;
  h: number;
}
export interface Frame {
  width: number;
  height: number;
  rgba: Uint8Array;
  /** original PNG bytes, kept so saveFrame() writes a real PNG artifact */
  png: Uint8Array;
  capturedAt: number;
}
export function toFrame(png: Uint8Array): Frame;
/** fraction (0..1) of pixels in `r` whose luminance exceeds INK_THRESHOLD */
export function inkRatio(f: Frame, r: Region): number;
/** count of distinct 4-bit (luminance >> 4) buckets present in `r` */
export function greyLevels(f: Frame, r: Region): number;
export function saveFrame(f: Frame, filePath: string): Promise<void>;
export const INK_THRESHOLD: number;
```

  <name>Task 1: Zero-dep PNG decoder + harness tsconfig</name>
  <files>harness/tsconfig.json, harness/png.ts, harness/selfCheck.ts</files>
  <behavior>
    Checks written into harness/selfCheck.ts BEFORE png.ts is implemented. Each
    check builds a synthetic PNG in-memory with zlib.deflateSync (no fixture
    files) and asserts decodePng() output:
    - Test 1: 2x2 RGBA (colorType 6), filter 0 on every scanline → exact 16 bytes returned, width/height correct
    - Test 2: 4x4 RGBA exercising filter types 1 (Sub), 2 (Up), 3 (Average), 4 (Paeth) on successive scanlines → decoded bytes equal the pre-filter original
    - Test 3: colorType 2 (RGB, 3 bytes/px) → expands to RGBA with alpha 255
    - Test 4: colorType 0 (greyscale, 1 byte/px) → expands to R=G=B=grey, alpha 255
    - Test 5: IDAT split across two chunks → decodes identically to a single chunk
    - Test 6: bitDepth 16 input → decodePng THROWS with a message naming the unsupported bit depth
    - Test 7: interlaceMethod 1 → decodePng THROWS naming interlace
    - Test 8: colorType 3 (palette/PLTE) → decodePng THROWS naming the unsupported colour type. Palette PNGs decode "successfully" into index bytes that a naive RGBA reader would happily measure ink on, so this must be a hard throw, not a fallthrough.
    - Test 9: bad magic bytes → decodePng THROWS
  </behavior>
  <action>
    Create `harness/tsconfig.json`:
    ```json
    {
      "extends": "../tsconfig.json",
      "compilerOptions": {
        "rootDir": "..",
        "noEmit": true,
        "allowImportingTsExtensions": true,
        "lib": ["ES2022"],
        "types": ["node"]
      },
      "include": ["**/*.ts", "../src/config/constants.ts"]
    }
    ```
    (`allowImportingTsExtensions` requires `noEmit`; the root tsconfig's
    `outDir`/`rootDir: src` must be overridden or tsc rejects the harness tree.)

    Add to package.json scripts: `"typecheck:harness": "tsc -p harness/tsconfig.json"`.

    Add to package.json (B5 — the harness has a hard floor on native TS type stripping):
    ```json
    "engines": { "node": ">=22.18" }
    ```
    And put a guard at the very top of `harness/selfCheck.ts` (plans 12-02 and 12-03
    repeat it verbatim in `harness/probe.ts` and `harness/run.ts` — three copies of
    three lines beats a shared module that itself has to be loadable):
    ```ts
    const [maj, min] = process.versions.node.split(".").map(Number);
    if (maj! < 22 || (maj === 22 && min! < 18)) {
      console.error(`harness needs Node >=22.18 for native TypeScript execution; this is ${process.versions.node}`);
      process.exit(1);
    }
    ```
    On Node <=22.5 every entry point otherwise dies with `Unknown file extension ".ts"`,
    which reads as "the harness is broken" rather than "upgrade Node". There is no
    fallback runner — adding tsx/ts-node is a dependency (D-02, D-11).

    Write `harness/selfCheck.ts` first — plain `node:assert/strict`, a `check(name, fn)`
    helper that records pass/fail, a `main()` that runs all checks, prints one line
    per check, and `process.exit(failures ? 1 : 0)`. No test framework (D-11).
    Include a small `makePng(width, height, colorType, bitDepth, rows, opts)` builder
    that emits real PNG bytes: `\x89PNG\r\n\x1a\n` signature, IHDR, IDAT(s) from
    `zlib.deflateSync`, IEND, each chunk with a CRC-32 computed inline (16-line
    table-driven CRC — do not add a dependency for this).

    Then implement `harness/png.ts`:
    - Verify the 8-byte signature; throw `Error("not a PNG: bad signature")` otherwise.
    - Walk chunks: 4-byte big-endian length, 4-byte type, payload, 4-byte CRC.
      Do not verify CRC on read (the simulator's encoder is trusted; we only need
      to reject structurally wrong input).
    - From IHDR read width, height, bitDepth, colorType, interlaceMethod.
      Throw naming the offending value unless `bitDepth === 8`,
      `colorType` is one of 0/2/4/6, and `interlaceMethod === 0`.
    - Concatenate all IDAT payloads, `zlib.inflateSync` the result.
    - Undo scanline filters in place: bytesPerPixel = {0:1, 2:3, 4:2, 6:4}[colorType];
      stride = width * bytesPerPixel; each scanline is 1 filter byte + stride bytes.
      Implement filters 0 None / 1 Sub / 2 Up / 3 Average / 4 Paeth exactly per the
      PNG spec (Average uses `floor((a+b)/2)`; Paeth predictor over a/b/c). Throw on
      any other filter byte.
    - Expand to RGBA: colorType 6 copies straight through; 2 sets alpha 255;
      4 (grey+alpha) maps grey→RGB and keeps alpha; 0 maps grey→RGB with alpha 255.
    - Return `{ width, height, rgba }`.
  </action>

    `harness/regions.ts` — import `DISPLAY`, `GLASS_LAYOUT`, `OVERLAY_LAYOUT` from
    `"../src/config/constants.ts"` (note the explicit `.ts` extension — required by
    Node's native type stripping) and build REGIONS by reference only. Per D-08 no
    coordinate literal may appear in this file except `0`:
    - FULL: 0, 0, DISPLAY.WIDTH, DISPLAY.HEIGHT
    - CONTENT: GLASS_LAYOUT.x, GLASS_LAYOUT.y, GLASS_LAYOUT.width, GLASS_LAYOUT.height
    - STATUS: GLASS_LAYOUT.x, GLASS_LAYOUT.statusY, GLASS_LAYOUT.width, GLASS_LAYOUT.statusHeight
    - TEAM_BAR: 0, 0, OVERLAY_LAYOUT.TEAM_BAR_W, OVERLAY_LAYOUT.TEAM_BAR_H
    - OPP_COMPOSITE: OPP_X, OPP_Y, COMPOSITE_W, COMPOSITE_H
    - PLAYER_COMPOSITE: PLAYER_X, PLAYER_Y, COMPOSITE_W, COMPOSITE_H
    - LIST: LIST_X, LIST_Y, LIST_W, LIST_H
    Each carries its own `name` matching its key.

    `harness/frame.ts`:
    - `INK_THRESHOLD = 16` — luminance above this counts as lit. The glasses render
      green-on-black and black is LED-off, so a small floor rejects encoder noise
      without rejecting the dimmest of the 16 grey levels (level 1 ≈ 17).
    - `lum(r,g,b)` = BT.601 `0.299r + 0.587g + 0.114b`, matching the greyscale
      conversion the host applies (research §1) so harness and device agree.
    - `toFrame(png)` = `{ ...decodePng(png), png, capturedAt: Date.now() }`.
    - `inkRatio(f, r)`: iterate only rows `r.y..r.y+r.h` and columns `r.x..r.x+r.w`,
      index `((y * f.width) + x) * 4`, count pixels with `lum > INK_THRESHOLD`,
      return `count / (r.w * r.h)`. Throw if the region falls outside the frame —
      a silently clamped region would make an assertion pass for the wrong reason.
    - `greyLevels(f, r)`: same walk, `buckets.add(lum >> 4)` into a Set, return size.
    - `saveFrame(f, filePath)`: `mkdir -p dirname` then `fs.promises.writeFile(filePath, f.png)`.
      Writes the ORIGINAL bytes — never re-encodes (D-09 wants a debuggable artifact,
      and this harness has no PNG encoder).
    Add a synthetic-frame helper to selfCheck.ts that builds a `Frame` directly from
    an rgba array without round-tripping through PNG, so metric checks stay independent
    of Task 1's decoder.
  </action>
